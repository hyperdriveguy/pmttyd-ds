# Actual Harbor reward-counter binding

`HarborTutorial::beginNativeRewardCounter` binds the finite
[native reward counter](NATIVE_HARBOR_REWARD_COUNTER.md) to its actual battle VM,
canonical pouch and genuine public sound owner. This factory admits only the
actual source victory predicate1 after all non-wait source event roots finish.
It also requires initialized tutorial/intro, no pending message, hit/damage,
attack or phase work, and an idle manager. These native admission checks do not
execute or acknowledge original btlseqEnd.

The original admission facade address and registration proof are captured at
fresh battle entry. Both are checked before borrowing its runtime. A copied or
moved facade cannot mint a counter for the original's VM, including while the
original remains alive. Retained callbacks pin actual battle allocation and
pouch address, current registration, source battle context and original facade
proof. Teardown/replacement revokes them before another read or write. The
counter keeps its runtime alive without a Runtime-to-counter ownership cycle.

The factory mints once per actual runtime. It retains a weak reference and a
separate minted latch: abandoning the counter cannot create a replacement that
re-awards the same accumulated stock. Native cancellation then remains pending.

Word/half/byte reads and EXP writes use the actual VM memory services. Sound
calls the genuine NativeBattleSound public On owner with original literal
802feaa8, `SFX_STAR_POINT_GET1`, already present unchanged in the source pack.
This produces a real public-slot request; it does not certify NDSP playback.
Missing/stale services remain pending. No synthetic effect handle, result,
source event or whole-End receipt is created.

The external ending coordinator must admit the real presentation, source
victory roots and PointGet before calling counter `start`. Counter Done certifies
only its own finite count/cooldown; it is not native teardown or field return.
The existing native completion factory is not automatically activated here.

The private actual-runtime regression uses explicitly TEST source conclusion
and event-retirement setup, then checks the real pouch increments once after
four simulation visits. Copies, redirected scene pointers, retained stale owners
and canceled/re-minted counters reject. It is not a full Crump playthrough.
