# Retained source weapon production for Harbor

The new portable owners retain the complete original weapon table
`80123ec0/d50`, affordability check `801268fc/6c`, target-count query
`80123d00/b0`, eligibility updater `80123db0/110`, and selection decision
`80123210/150`. They replace retrying the synchronous references after a
missing message, cost, sampler, or UI dependency. The source references remain
available for differential tests; they are not installed as retry adapters.

## Source order and private outputs

Table entry resolves the acting unit, captures M and pouch, tests wrapped M,
requests its own cursor, then initializes its own private count0. Cursor output
starts unknown. Ordinary Jump/Hammer levels are read independently, icon helpers
acquire fresh pouch history, and first-row override follows original name/icon
production. Badges, signed inventory IDs, explicit null-item substitute, original
empty-item row with both ordinal stores, captured Special mask/live pointers,
and indirect party output all retain their original branches and write order.
Source row padding and unrelated fields survive. Positive publication alone
writes count/clamps only the upper selected index/decreases positive scroll;
the final eligibility child completes before the current private count returns.

Original private cursor/count words are native retained cells, not invented
addresses for guest SP. The actual indirect party child receives a typed stable
count pointer. Only that original output owner is exposed; arbitrary aliases to
unwritten source stack storage are not manufactured. Unsupported cursor queries
complete without writing the optional output. An actual consuming source site
holds if that output remains unknown, without replaying emitted rows or lookup.

The target-count wrapper guards null weapon and absent script before cost.
Cost denial returns-1; every nonzero cost result admits the real private sampler.
It preserves raw enemy-belong for direction addressing and signed-byte conversion
of the negated direction. Its source-private candidate buffer must be a real
caller-owned VM scratch allocation, distinct from live B+428. The updater
captures its cursor count once, clears each visited enable/reason pair before
the retained target query, and preserves fresh later-row weapon reads.

Decision captures its acting unit before table rebuilding and uses current
B420 when building final sampling arguments. It resets target rank after the
sampler completes. The preference branch follows the actual original listing:
`801232c4` loads weapon+68 **before** `801232c8` loads the permutation byte,
and before the candidate Unit/Belong children. That branch stays captured through
those holds; the next row rereads flags/count. This differs from the old
synchronous reference, which rereads flags after the children. Both preference
policies retain signed side/count/permutation semantics, last-same versus
first-different choice, and low-byte final publication.

CheckWeaponCost captures GetFp before the existing retained GetWeaponCost
child, omits AP entirely if signed FP is insufficient, then reads fresh AP and
weapon+12. It does not spend resources. Ordinary item0/baseFP0 reaches the
existing packed cost owner's free branch without invented badge/pow/reduction
providers. Payment remains a separate original child.

## Native composition

`HarborSourceCommandUi`. Actual VM registry/status/pouch/badge/icon/GetData/FP
leaves are supplied at their original boundaries. Messages remain actual
source-key lookups; the native party adapter remains held until its genuine
callback and private-output owner are provided. Power/fctiwz remain explicit
optional numeric providers, not successful stubs or guessed costs.

The Packed factory reserves its already provisioned MenuRam+40 scratch domain
as explicit native private sampler storage. It never aliases source guest SP or
live battle target storage. The native sample/update bridge executes existing
complete packed source helpers only after actual platform numeric callbacks are
present, and never returns unavailable after they write. Unbound Monosiri
attribute domains are conservatively refused before sampler entry. That is a
native admission frontier, not an original early return. Actual actor/part
memory must be fully admitted and stable through each synchronous group.

The dynamic-B correction captures the actual source current-battle cell once
at UI binding. Its weak-runtime-guarded current callback checks actual current

proof is still required, including after original Cold Init allocates work.
Class/weapon diagnostic row capture uses that B and optional VM readers; it
never writes source fields or converts a failed projection into a repeated
completed Input. Actual camera/frame drawing must read real source rows and
alone produce UI readiness. This batch does not call Presented helpers.

## Lifetime and validation

All owners pin function/user/memory/lifecycle/current/private-buffer identities,
retain operands before calling children, reject reentry and reset during an
invocation, and latch observed current loss. Reset abandons metadata only;
callers cannot use it to replay successful siblings. The UI owns an independent
native provider record for cost-service identity; the actual weak runtime is
locked by its outer invocation before any callback or VM access. The record
neither claims a source generation nor creates a runtime ownership cycle.

Strict host tests compare table traces with the synchronous reference for all
local routes, signed levels/items, source mutations, late overrides, captured
Special masks and party counts. Every external boundary is held twice, including
separate GetData/unknown-output checks. Evaluation tests cover guarded returns,
raw-side private addressing, captured eligibility counts, fresh AP, every held
boundary, and retirement. Decision's callback-mutated preference fixture follows
the actual listing rather than the stale reference ordering. Integrated UI
postimages repeat physical navigation/cancel, source TargetSetup/End and
readiness-denial tests through the new owners.

ASan/UBSan, strict ARM syntax of all new files and private postimages, and the
read-only ISO verifier are recorded under `artifacts/harbor-weapon-table`.
LeakSanitizer is disabled under this ptrace executor. Actual Packed/Game factory
execution requires root's full fresh ABI graph; these focused tests do not mix
new Packed storage with an old Game archive. Cold UnitSetup/Main/FirstAct,
actual sound ownership, queued native class/weapon/target drawing, action/turn
completion and unchanged Crump story return remain separately required.
