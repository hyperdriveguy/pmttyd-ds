# Portable original damage orchestration owner

2026-10-13 source-based implementation of BattleCheckDamage800fb01c/0xa00 and
BattleCheckPikkyoro800fde2c/0x1a8. The authoritative branch/call contracts are
[damage orchestration](BATTLE_DAMAGE_ORCHESTRATION.md) and
[counter selection/tail](BATTLE_COUNTERS.md). Original executable bytes stay
private. The read-only verifier pins both full bodies, the five effect constants
and13 literal capture/guard/multiply/divide/stop/help instruction sites.
It does not execute Dolphin or establish original-runtime timing/raster parity.

`checkPackedBattleDamage` works on actual packed unit/part/weapon addresses and
injected source service providers. It initializes the original48-byte counter
record, captures current battle before the null-defender return and preserves
all local branches. It runs the existing recovered packed counter selector;
its register return is deliberately ignored. Source memory/storage fields and
raw low-byte code OR behavior remain visible to later providers.

The owner preserves separate superguard equality5 and ordinary signed>3 reads,
source mode2/3/4/default response routes, the actual Nice object payload+1c0.75
write and original sound-key identities. It preserves part event exits before
calculation, HP then FP sharing one code word, hit-count narrowing after both
calculators, status suppression and ordered code overrides, the otherwise inert
Freeze RNG draw, audience classification from calculated values and zero-amount
direct damage calls. Pattern14/16 still consume a draw after attribute immunity
clears their local pattern.

The counter tail adds independently wrapped/signed-truncated50/100 HP amounts
for each original gate, retains negative results and the zero-only fallback1,
uses the original defender part for attacker status calls, performs explosion/
sound/fog/AC-stop/help/direct-attacker/optional-defender-event ordering and
returns-1. AC stop receives the battle captured at entry even when a calculator
changes the current-battle global. Attacker sequence and defender low byte are
published before direct damage in superguard, after direct damage in the
ordinary path. The event callback's negative-return/output/calling-ID protocol
remains a separate owner.

Pikkyoro captures its own current battle, reads original five source gates,
preserves sole-choice/no-draw and descending multi-choice rank selection, ORs
rather than replacing flags, and still performs selection for a null destination.
No gameplay meaning is invented for those flag masks.

Providers must execute their actual source helpers. Effect allocation, sound,
audience, damage calculators, status infliction, revival, hit-event lifetimes and
AC/help callbacks are external services. Assertions require callbacks only when
an executed path needs them; weapon flag20000 short-circuits guard providers.
The owner does not insert PreCheckDamage or infer result/turn/story progression.
This increment is compiled for host/3DS and tested at the service boundary; it
is not yet bound into HarborTutorial or a replacement for TrioAttack's scoped
ground-damage adapter. Native integration must supply real providers before
retiring either existing path; no fake Nice/effect handles or forced service
acknowledgments are introduced here.

Tests exercise every superguard byte0..5, fresh guard-result reads, null defender,
zero/FP-only/negative amounts, FP code overwrite, status priority/suppression,
reaction-only results, hit-count/sequence narrowing and publication order,
both special event routes, retained RNG after immunity, actual packed spike/
part counter selections, three odd/negative/overflowed half contributions,
source status recipient/part arguments, captured battle, and every subset/rank
of five Pikkyoro choices. These are native unit-test observations with explicit
provider fixtures, not original execution observations.
