# Shared original weapon-table production and eligibility

The new packed builder implements all local routes of original
_btlcmd_MakeSelectWeaponTable80123ec0/d50: independently admitted ordinary
Jump/Hammer levels, original badge arrays,20 signed inventory slots, empty-item
descriptor, captured Special mask/live weapon pointers, and source key1 party
callback delegation. Original message-key lookup and icon services are required;
no English label, placeholder weapon or fabricated party row is supplied.

Caller-owned private cursor/count words model the separate source stack outputs.
Count0 is written after the cursor request. Each service-visible count mutation
is retained when deriving later rows and incrementing count. The party provider
receives the actual count address. Descriptors preserve untouched padding and
unused fields/rows. First ordinary replacement occurs after icon/name; inventory
null weapon uses only its explicit substitute and its name-before-icon order.
Empty inventory retains the real dummy row and both ordinal stores.

Positive final count publishes cursor count, clamps only too-large signed index,
and decreases only positive scroll under the original wrapped six-row comparison.
Empty/nonpositive output preserves previous cursor state; negative indices/scroll
are preserved. Eligibility update occurs afterward, then the current private
count is returned. Unbound party/update providers retain partial stores and
return a port nullopt, which is not an original table count.

The complete shared target-count wrapper preserves null/event guards before
cost, accepts any nonzero cost result, retains raw enemy-belong for direction
addressing, applies signed-byte conversions/negation and samples only into a
private buffer. The eligibility updater captures its row count once, clears
only enable/reason, uses fresh row weapon pointers and source signed reason
branches. Underlying cost/sampler/party/message/UI services remain separate
native bindings; the tutorial does not yet display or confirm these generated
rows. These modules are required dependencies, not a substitute menu or proof
of complete gameplay integration.

Native trio launch now uses party domain6/cursor4c8 for Goombella instead of
Item domain2/cursor51c, and Hammer uses cursor4bc rather than Jump4b0. Existing
physical command/target controls and original labels/icons remain unchanged.
The live Goombella fixture checks domain6 and its attack-class record16f55.
