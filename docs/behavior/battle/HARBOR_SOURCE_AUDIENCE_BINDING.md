This is a native binding of source effects, not evidence that normal opening gameplay has reached or completed the cold parent.

The source identities are US revision 0. `verify_harbor_source_audience.py` pins 18 whole helper bodies/data spans; the retained parent has its own independent verifier. Source addresses identify recovered functions and fields, rather than provisional gameplay measurements.

## Lifetime and availability

Creation requires a real pool allocation token, source B pointer, strong caller lifetime/current proof, source data and all required numeric callback identities. Resume rejects allocation-address reuse, replaced SDK userdata/callbacks, stale cache aliases, changed immutable inputs and reentry. Retirement only invalidates native metadata; it performs no guest End, reset, file release or allocation cleanup.

The caller must keep actual guest storage and memory-provider topology stable through each synchronous total actor read/write and numeric callback. A `current` callback may not retire/free/mutate these owners while returning true. The owner does not supply a VM lease by inventing missing memory. Unknown or unavailable optional inputs hold; admitted total-memory operands are required to remain readable/writable.

Unbound noise, positive seat/entry and positive AddAudienceNum suffix providers remain unavailable at their exact source boundaries. A frontend callback must own its whole retained child and return engaged zero only for actual completion. Normal Crump configuration currently loads both real TPLs and stops at `BattleAudienceSoundNoiseAlways801a0b88`. There is no fabricated silent-success or audience-ready flag.
