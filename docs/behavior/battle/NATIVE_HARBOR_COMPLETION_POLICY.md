# Native Harbor completion and owned teardown

This bounded native policy consumes the actual manual Harbor runtime. It is not
whole original `btlseqEnd`, `BattleEnd`, reward presentation, field reconstruction,
or original sequence-return timing. It does not advance story, publish a field
result, select sequence 2, or acknowledge an original field wait command.

## Original result and export basis

The existing complete source conclusion predicate publishes alliance results;
`battleInitialEndResult` selects original values 1, 3, 4, or 5. These are already
the field result values. Success 1 is not encoded 0 and no increment is applied.
The native completion factory currently admits only result 1, after recomputing
the genuine idle source predicate. Other result routes remain unavailable.

Original ending state 1f at 802165b4 tests actual setup S+4 mask 0x40. Only that
condition admits nonpositive Mario HP becoming 1 before export; ordinary victory
does not heal HP or FP. `BattleSetMarioParamToFieldBattle` 800f8a68 unconditionally
exports Mario, then exports nonnull active party. The original packed exporter
80126f00 writes Mario current HP/FP and partner current HP/raw saved status fields;
it does not restore maxima. See [the exact wrapper](PARTY_FIELD_EXPORT_AND_SNAPSHOT_CALL_DOMAINS.md)
and [ending teardown](ENDING_HEAP_FREE_AND_REMAINING_UNIT_TEARDOWN.md).

## Native owner and order

`HarborTutorial::beginNativeCompletion` requires the genuine conclusion, no
current pending service or live hit-event root, no active manager invocation,
no retained menu-file invocation and no incomplete actual source display pass.
All other live source events must finish; only actual known ordinary wait-script
roots may be cancelled. This check remains valid when UnitDelete has removed the
registry slot and hidden its former U+0x2b4 handle. A strong completion owner pins the actual runtime; the runtime retains only a
weak reference. Actual public registration, current BattleWork global and real
allocation token are checked before borrowed VM access. Destruction/replacement
of the public facade revokes permission. Existing facade copies share their
existing registration, consistently with the other Harbor factory bindings.

Once admitted, simulation ticks freeze. Dropping a partially executed completion
owner does not authorize restarting teardown. It is an explicit cancellation
frontier, not a retry from the beginning. The native caller retains the owner.

The completion owner performs these native steps once, preserving successful
prefixes across holds:

1. Retire actual menu presentation outside rendering, after synchronization.
2. Retire actual native battle music/voice playback through the real Audio owner.
3. Delete actual events in this dedicated battle VM using original event deletion.
4. Apply the original conditional HP rule, then call the original Mario/party
   packed export and capture all known canonical pouch bytes.
5. Retire only this battle sound owner's actual public slot births.
6. Free this adapter's actual SDK UI allocations and retire its native weapon
   presentation generation, then invoke original menu-file
   End 80119d74 through its actual file owner and retained cursor.

Callbacks and their actual owner lifetime are fixed across holds. A true native
retirement response means completed work; a false provider retains its own partial
work. Reentry is rejected. Foreign sound incarnations survive teardown even after
source handle wrap; see [slot ownership](../audio/NATIVE_BATTLE_SOUND_SLOT_RETIREMENT.md).
The native SDK UI set is specific to this manual adapter. Actual cold-source map
allocations and whole UnitDelete/Stage/Audience/Break teardown remain separate.
The source menu descriptor bytes are intentionally not cleared by original End.

Only completed teardown exposes a receipt containing unchanged result 1, the
canonical pouch and actual battle lifetime. It does not write scene result or
original I+0x10. The native caller must stop selecting frontend tutorial track 12
as soon as completion owns retirement, so a later audio update cannot reopen it.
Menu5 supplies actual `Renderer::retireNativeHarborMenu`; Nice8 additionally
supplies `Renderer::retireNativeHarborNice` for its separate native vertex arena.
Both belong in the outside-frame presentation retirement callback. The PCM owner supplies
actual `Audio::retireHarborBattleAudio`. These are native resource operations,
not an original BGMOff/source event completion claim.

## Canonical field pouch return (2026-11-08)

Normal staged Game entry now calls `beginHarborTutorialFromField` after the
original beforebattle adapter reaches its retained setup2 request. An admitted
native field passes its exact `NativeMarioConstructor` and canonical pouch via
`HarborTutorial::beginFromNativePouch`. Equal bytes in another object, or the same
object with a foreign shared-pointer control block, do not satisfy admission.
Ready/current owner, actual SDK guest address and canonical backing are checked
before original battle initialization and again after its first manager visit.
A failed partial Begin remains partial and cannot silently replay initialization.

The battle retains that constructor, packed object and guest address for its
lifetime. Game contributes a weak native-facade proof plus a pure current
predicate: check proof before borrowing Game, then verify its admitted public
constructor and current canonical pointer/control blocks. Copies, moves,
destruction and checkpoint reconstruction cannot inherit field write permission.
The callback holds only weak field references; it adds no ownership cycle.
The binding reuses the existing Game battle-sequence facade registration, whose
last-member declaration retires it before owned resources. No duplicate lifetime
registration/allocation is added. Existing const-reference/fresh legacy battle entry retains its prior behavior
and has no canonical-return permission. Absent legacy inventory stays absent.

`HarborTutorial::commitNativePouchReturn` requires this actual facade/runtime,
its retained native completion owner and that owner's completed, current receipt.
It compares unchanged result1, all packed bytes and exact battle lifetime pointer
AND shared control block, including equality with this runtime. Public receipt
fields alone, a conclusion scalar or an uncompleted owner authorize no write.
The caller also supplies its admitted field constructor and current canonical
pouch; both must match the retained entry owners/control blocks before and after
receipt validation. Reentry is refused. Field/facade ownership is rechecked after receipt validation
because native completion services may be consulted there.

The first valid commit uses `NativeMarioConstructor::adoptPouchSnapshot`: preserve
its busy, Entry and producer guards; write the existing actual SDK-backed bytes;
latch only after success. It allocates no replacement pouch and updates no story,
result or sequence. Later valid visits return the same object without copying;
later field HP/inventory edits therefore survive. `Game::commitHarborPouchReturn`
refreshes its legacy/UI HP mirror from that returned object. Replaced canonical
pointers and foreign physical VM backing revoke admission without writes.

The normal entry helper is installed; the return API awaits the real ending
coordinator. Nothing calls it from HP/conclusion alone. The complete victory/
reward/finishing/audio/fade/teardown owner and actual field presentation/ticket
return must still be composed. Only after those complete may the original field
wait observe result/sequence and execute its remaining source cleanup/afterbattle.
This is a bounded native resource handoff, not whole original End or a completed
Crump playthrough. The exporter and mask40 behavior remain unchanged.

The existing completion-facade regression now builds the real shared UI/Mario
constructor, runs all132 original beforebattle adapter commands to setup2, and
uses the production Game entry helper. Its separately labelled TEST status27/
root-retirement prefix admits the actual native completion owner; it does not
prove physical gameplay or original fatal/ending scheduling. Tests cover held
presentation/music, forged result/bytes/control blocks, copied facades, pointer
replacement during receipt validation, an actual field NPC producer lease,

preservation and foreign backing rejection. Existing export tests retain
partner snapshots and source conditional nonpositive-HP behavior coverage.

## Presentation retirement across held completion (2026-11-08)

Actual `Renderer::retireNativeHarborPresentation` now requires the original
current Harbor facade and an outside-frame call, in addition to matching all
retained presentation owners. After real `C3D_FrameSync`, it retains the exact
facade proof and weak runtime identity independently of the reward/fade owners
it frees. Copied facades and same-address pointers with foreign shared ownership
cannot admit retirement. A later battle at the same C++ address cannot inherit
this barrier.

The normal Renderer frame entry checks that barrier before any source-menu,
map, actor, audience, HUD or overlay preparation. During held completion it
submits opaque black clears for both actual native targets and returns. A held
FrameBegin or failed target submission retains the barrier; it cannot fall
through to battle re-import/draw. This uses the existing Citro3D frame/target
operations and allocates no frame-local resource owner or geometry. Shutdown
retires the barrier before target destruction.

This is durable native presentation retirement, not a finishing opaque-frame
receipt, field-resource reload, original End acknowledgment or permission to
advance story/result/sequence. The caller must still retain actual completion,
stop audio, export the canonical pouch and prepare/admit the incoming field
presentation before allowing field rendering. Game/Harbor replacement is not a
field-return shortcut. Focused tests execute the actual retirement adapter with
real admitted Harbor facade/runtime and a TEST GPU boundary; no hardware or
pixel claim follows from that fixture.

A still-current retirement barrier also participates in preflight: another
genuinely admitted live facade/runtime cannot overwrite it after the other GPU
owners have already been freed. Rejection precedes synchronization or resource
changes. Assignment/move/destruction retires the old immutable facade proof,
so a new incarnation can acquire its own barrier after normal admission.
