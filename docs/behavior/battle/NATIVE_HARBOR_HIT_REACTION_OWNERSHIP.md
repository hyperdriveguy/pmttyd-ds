The tutorial runtime now supplies actual VM event lifecycle services to the
original [BattleRunHitEvent/Direct helpers](BATTLE_PACKED_COUNTER_AND_HIT_EVENT.md#hit-event-lifecycle).
An original damage producer can dispatch the installed hook or an explicit
original direct script through the native scene bridge. No development button
selects a hit, HP decrement, victory or field result.

Ordinary dispatch preserves the source code40/data46 presence guard and null
installed-hook skip. Direct dispatch retains cancellation order2b4,290,29c,2a8,
even for null script, with clear-after-deletion stores. Nonnull scripts create
real priority10/flags20 roots, retain actual registry owner IDs, and store full
code278 and root ID2b4. Source children inherit their actual parent owner.

`damageActive` observes actual live damage IDs over the admitted four-owner
native roster. It neither uses an elapsed timeout nor clears finished handles;
complete original cleanup remains its separate owner. The scheduler bridge
refuses overlapping phase/attack admission while a reaction is live. A phase
canceled by a hit is distinguished from natural intro completion. Pending-service
diagnostics retain their event ID and clear when replacement deletes that event.
The tiny original system hook can finish through its own source delete opcode.

Source main-body ID2d4 now copies the flagged original part definition during
bounded entry projection. The complete existing body-part getter is registered.
This does not install complete UnitEntry/display allocation or animation coverage.
