## Rotation source order

The caller admits complete actual EVT, memory and numeric services for the
entire synchronous invocation. There is no partial provider acknowledgement,
rendering side effect, async callback or unavailable-as-zero path in this owner.
Native missing numeric providers hold before entering the whole leaf.

Both event wrappers resolve/translate the actor first. Their XYZ operands are
EVT integers, not event float operands. Original private xoris/lis transport
converts signed32 using the actual double bias at802ee608 and source binary32
subtraction rounding. This owner reads the real bias, uses the actual platform
double subtraction/rounding, and owns the typed private values; no guest stack
address is fabricated. Integer differences are exact in double in this domain.

Raw Y/Z operands are captured before the preceding axis's conversion. The
fresh global Battle is captured before the final Z conversion, then passed to
the source unit lookup afterward. Tests mutate those locations at the bias-read
boundary to distinguish the required captures from later rereads.

AddRotate processes X/Y/Z sequentially. Each axis reads its current value,
performs source single addition, invokes the existing complete
`revisePackedJumpAngle` owner, stores the result, then reads fresh full-turn and
stored-result values before the optional source-zero store. SetRotate first
calls whole GetRotate with three owned private outputs, restores each axis
whose **raw** operand equals -250000000, and normalizes/stores/clamps in the
same order. All three old axes are read even when no sentinel is present.

The existing angle helper supplies original double fmod, binary32 rounding,
NaN replacement, signed-zero and negative-turn adjustment from actual source
constants. Its platform/libm adapter is the existing explicit native numeric
policy, not a claim of complete Gekko FPSCR equivalence. No alternate easing or
render-frame arithmetic is introduced.
