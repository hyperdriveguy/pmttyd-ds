# Native Harbor source victory event

The positive reward coordinator can start the actual Mario data-key40 root
from the admitted battle registry. The source owner ID, priority10/flags0 and
tracked U+2a8 event ID belong to that actual VM. A retained root ID prevents
duplicate creation if the tracked store holds. Polling checks the actual root
ID and active bit; it does not use animation duration as event completion.

The immutable admission facade proof is checked before borrowing its runtime.
Copied, moved or retired facades cannot start or certify the root. Admission
requires the current positive reward counter and the Crump null-party domain.
A native finite label/operand preflight checks actual mapped source words and
constructor capacity before creating the event; missing mappings remain held.

Focused tests establish the conclusion boundary with TEST-only source status
and removal of earlier roots, then create and execute the genuine Mario root.
They verify original M_V_2 and actual source1000ms event retirement, once-only
root/owner/tracked ID, and copy/stale rejection. Host, new-runtime ASan/UBSan
and strict ARM syntax checks passed. The parent core is uninstrumented and
leak scanning is disabled in this environment. These tests do not establish
physical victory, reward award, whole btlseqEnd or field return.
