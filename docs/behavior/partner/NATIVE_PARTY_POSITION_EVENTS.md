## EVT ordering and retained native holds

Capture args before Mario query, then read raw selector even on initial first=false.
Initial first=false returns2 without creation. First=true with a signed nonnegative
Mario current byte returns2 before kind/coordinate resolution. Native adaptation
retains a reached synchronous source invocation across resource waits, so a later
VM first=false does not discard its constructor or falsely complete it.

Explicit setter resolves kind, X, Y, Z through getEventValue. Previous setter
resolves X/Y/Z first, then reads the captured Mario's saved kind; zero returns2.
Each signed32 coordinate rounds to float, matching the original signed-bias route
in the supported nearest-rounding domain. Encoded event float operands therefore
truncate through the original resolver before construction. Neither path uses
float operand resolution or preserves those fractional coordinates.

Selector, args address, resolved values and constructor return remain retained.
Nonnegative result publishes low byte to the originally captured Mario slot only
after full construction; a negative result returns2 without publication. Native
byte admission is raw selector0/1; original unchecked arithmetic outside that
range is not simulated. One adapter owns one invocation, pins EventEntry pointer/
id and memory identity, and requires the caller to discard it at real event
retirement. Reused entries cannot retarget an active continuation. Once value
resolution starts, subsequent resolutions require the same operand providers.
