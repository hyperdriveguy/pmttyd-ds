# Native field Mario key admission

`NativeFieldMarioKey` binds actual native Mario control storage to the whole
existing `fieldMarioKeyEvent` helper for original `evt_mario_key_onoff800e7474`.
The [existing source contract](NATIVE_MARIO_KEY_AND_BACKGROUND_PREPARATION.md)
and [complete wrapper/leaves](BERO_KEY_LEAVES_FRESH_ACTOR_OWNERS_AND_NEXT_ROAD_FRONTIER.md)
remain authoritative. This adapter supplies admission and lifetime, not a new
control implementation or a scene-only counter.

The immutable binding copies actual `FieldMarioPreparationWorld` callbacks and
userdata once, pins independent strong userdata lifetime and actual native host
registration, and captures the actual caller VM intrinsic registration. Both
registrations precede the current predicate and borrowed fields. Root's Game
predicate must prove its actual current Game slot, Encounter facade/VM and Harbor
admission before Game access. Copies/restores must use fresh admissions. Source
and native state are single-threaded and stationary during the admitted
synchronous helper; callbacks are total in their admitted typed field domain.
No holder→adapter→holder ownership cycle is permitted.

Native preflight admits only actual active registered entries with known E+18
argument pointer and a single raw immediate 0 or 1. Unknown words and encoded
operands hold before source stores. World admission may refuse before all body
effects. Such unavailable calls have not performed a source prefix and may retry.
The actual VM's complete evtGetValue operand service supplies the admitted
immediate resolution, including its real current-context lookup. The whole
helper preserves the captured argument pointer, unused initial Mario lookup,
raw operand read/resolution and fresh leaf pointer lookup. Actual source Mario
KeyOff/On own flag8, wrapping signed byte39 and final rereads. Real partyKeyOff
and KeyOn are return-only US bodies: no party lookup or invented effect is added.

Game's existing `fieldMarioPreparationWorld()` binds those fields to the actual
`fieldMarioBattle.flags/keyDepth` owner and updates native `fieldKeysOff` while
preserving independent acquisition/reward locks. Root can pass that actual world
under the current proof. Do not use `HarborEncounter::keyDepth` or booleans in
place of the actual shared counter. The adapter neither opens a menu nor samples
physical input, and does not alter button timing.

All invocation reentry is rejected. Host/VM/current retirement rejects before
borrowed access and permanently removes admission. Actual host mutation during
a synchronous helper is outside the stationary service contract; after-body
identity loss cannot restart that owner and replay stores. No unavailable child
is acknowledged by a boolean fallback. Non-key preparation families remain with
their own actual providers.

Tests exercise actual typed native Mario flags/depth with nested owners,
underflow/wrap, zero-only unlock, refused admission without setters, unsupported
raw operands, callback reentry and host/VM destruction. The fresh actual event
fixture runs the real NPC Entry/placement and original beforebattle event with
only the frozen GetPos/ENVOff and this key child admitted. Its typed Mario field
backing and trigger-zone coordinates are explicit TEST native constructor
inputs, not original complete Mario/FieldArea initialization receipts. Every
later missing source callback remains held. No Game integration, story edit,
legacy dialogue replacement or normal activation is included.
