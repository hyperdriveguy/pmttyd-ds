## Resolve the actual requested source name before returning a center

Shared full-parent into_info publishes LW3 as live VM GP+11c. Read the name
through the current shared EventAddressSpace,not FieldBeroInfo's standalone
85000000 incoming alias. LW6 is the actual original guest XYZ pointer;read its
three signed words through that same address space. Respect the original
normal callback's captures and resolution order before invoking pure geometry.

A reusable Game center provider can use existing real static ROAD metadata:

1. Establish Game.progress.room,FieldMapFlags.room and actual active collision
   ownership agree with the requesting area. This is provider admission,not a
   source implicit room conversion or proof from a numeric checkpoint alone.
2. Resolve the actual source name with FieldMapFlags.hitSourceNode(name).
   This correctly ignores disabled-query flag1 while excluding runtime80.
   Do not use hitEnabled as a substitute for original hitNameToPtr semantics.
3. Select exactly one RoadWarp whose source is the current room and sourceNode
   equals that returned original node. loadWarps already checks unique
   source/sourceNode and reciprocal arrival pairing;the original selected
   name must still establish the node identity here.
4. For the verified static leaf domain,return engine XYZ={road.x,road.centerY,
   road.z}*100. x/z/centerY are native-scaled source center data. spawnXYZ and
   current/final Mario coordinates are not the named hit object's center.

All8 shipped ordinary ROAD markers are source-proven transformed leaves with
one part and matching exported centers in
artifacts/outer-bank-road-leaf-centers.json. This is a finite static-source

and rejects any selected node with children. This admits the existing static

This validation does not establish arbitrary runtime-transform support.

Game.fieldBeroPosition->center is a cached result from one previously admitted
arrival calculation. Existing standalone adapter returns it while ignoring

another incoming name/node or source event mutation can make it stale. The

## Genuine floor query and numeric boundary

Reuse fieldShadowRay only after actual same-room collision readiness has been
established. It queries downward raw geometry without Mario support filtering
or Q1000 hit rounding. Normal helper needs direction(0,-1,0),maximum1000000
engine units,origin at computed P.Y exactly. A genuine miss retains centerY;
an unresolved tagged hit owner holds. Do not raise origin37,force a floor hit,
substitute groundAt or filter only Mario-standable triangles.

fieldShadowRay uses process-global staged collision. Its empty result currently
has unresolvedObject=false/found=false even when no head/ground data exists.
The simple adapter `{!unresolvedObject,found,point.y}` alone would turn unloaded
geometry into a fabricated source miss. Geometry readiness/room ownership
must therefore be admitted outside that returned flag. A candidate Game inside
CollisionTransition can legitimately query its staged target geometry;an
unrelated Game must not query the current global room by coincidence.

This provider presently owns static geometry and named flag overlays. Arbitrary
runtime moving HitObj matrices and additional dynamic object collisions are
separate domains;do not claim the finite static ray resolves them merely
because it returned a farther triangle. Unknown closer tagged owners already
prevent success through unresolvedObject.

Existing numerical adapters are standard double sin/cos then float32, C++
std::fma(a,b,c),and negative fused product/subtract `-std::fma(a,b,-c)`.
Retain source binary32 step order and mode==1 adds180 with no heading wrap;
fixed30 start radius differs from queried length. These are named numeric
adaptations,not proven bit-equivalent Gekko SDK trig/FMA. Distance0 and sentinel
X100000 preserve the distinct source P/F behavior already documented.

Do not stop at returning FieldBeroPosition. The original callback publishes six
mutable raw IEEE globals in this order:SX8041e9f8,SY8041e9f4,SZ8041e9f0,

## Party setter uses a different current owner from previous-party bytes

evt_party_set_pos800eb558 reads raw selector operand0. Zero loads process
global current party index8041ead0;any nonzero selects literal slot1. It does
not use Mario245/246, saved kinds247/248, marioGetPartyId or registry.current.
partyGetPtr800bf1b4 returns actual null for negative indices,otherwise reads
pointer table8041ead8+4*index without an original upper bound check.

Actual null completes2 before any coordinate operand read. Unknown native
current index is not proof of null and must hold before calling a provider
which asserts it is known. Native indices>=2 are an unadmitted pointer-domain
access,except where another source callback has an earlier no-lookup return.
For raw1,the current global need not be read or known at all.

Original boot BSS sets8041ead0=0. partyInit800bd6ac clears only two pointer
slots and does not reset this global. Existing Game.fieldPartyCurrentIndex is
an explicit optional boot0/session-retained view and is appropriate when its
provenance is known. Fresh boot0 with actual null slot0 is a real completed
raw0 branch;both Mario previous-party bytes may be255 while this global is0.
Native restore retains the global view independently of the reconstructed
registry. Do not alias it to an arbitrary active follower or treat checkpoint
knowledge as a new original writer. The bounded setter provider should use
this real owner,actual slot pointers,and preserve lookup-before-float order.
