# Shared native source map process

This binds original field CPU loading to one already-ready native camera,
shadow, UI and animation VM. Source lightInit/mapInit run at ordinary startup;
source room loading remains a separate retained operation. The first unavailable
GX capture child is intentionally held. This is not completed mapLoad, native
map rendering, original pixel parity or an end-to-end prologue receipt.

## Actual allocation and source data

`NativeMapProcess` borrows the real primary map pool from globals8041e808/root
and8041e818/length. Its SDK heap1 handle/start/end and allocated-list node remain
at their existing addresses. Binding validates the cold inner map header, never
resets a root or recreates a heap. The complete actual payload is isolated into
stationary backing at the unchanged guest address. SDK node headers, inner map
allocation headers and all map data share that actual process. Retirement returns
owned primary bytes to VM RAM and preserves foreign replacements; it fabricates
no SDK free. Stop consumers before destroying any owner.

The two light banks and map Work are actual heap0 __memAlloc returns, allocated
only at their reached source children. Providers retain exact SDK effects and
null returns. Stable native backing publication is separate from the original
wrapper clear/cache operations. Original mapInit explicitly clears Work again
after pointer publication; a null return holds at that memset without another
allocation. Original lightInit may finish presets with null banks; normal native
initialization separately requires both banks and nonnull map Work. Backend
currentness checks actual SDK0/1 roots, list membership, node extents and physical
mappings, rooted in the ready camera/shadow/UI/animation process. It does not
recursively call the aggregate map owner.

Original map/loader/hit/light constants merge byte-for-byte with existing VM
inputs. Matching inputs keep their current backing. The relocated975520-byte
scene at8a000000 in the constructor-fixture pack is explicitly omitted; native
loading obtains original raw D/T/C through the original DVD worker. UI archive
descriptors803dbff0 remain their real process records. Private stacks/table/name
and light formatting scratch use admitted disjoint addresses; none are asserted
to be original GameCube allocations. Missing/conflicting inputs retain failure.

FieldMapFileOwner pumps the complete original DVD manager/sort graph using the
existing exact rounded harbor transfers. CPU file IO replaces physical disc IO;
OS thread startup/timing is not reproduced. Queued Close requests retire through
that worker even while the parent is held later. Camera road loading uses the
existing camera4 table slot/record and same DVD worker/map allocator. The source
shadow projection getter reads its initialized process value, including nonzero
values; zero is never substituted as a permanent answer. Lights are created by
the one reached map parent loop, not by a second fabricated table import.

## Execution, native fence and CPU-only cache domain

FieldMapSourceOwner executes straight-line source prefixes inside a synchronous
RAM-cache borrow. The borrow ends before the exact queued child executes, so
real allocation, mapping mutation, nested SDK borrows and DVD delivery remain
legal. Accepted child results/next PC retire outside the borrow; each source
case is charged once to the native visit budget. A wait retains the exact
request, PC, operands and partial effects. Invocation guards prevent reentry;
semantic providers and consumers stay frozen on the owning thread. No RAM
pointer, identity cache or budget receipt survives a prefix/hold.

The map SDK admission is similarly restricted to one synchronous primitive.
Full ownership proofs bound each call; raw SDK constants remain fresh reads.
Matrix/vector outputs are restricted to the primary pool or private map stack,
preventing admitted SDK stores from changing protected heap/global metadata.
The reciprocal-square-root callback exits that admission, checks ownership
before and after delivery, and cannot restore admission after ownership loss.
Native finite libm/estimate policy is explicit, not a measured Gekko seed model.

Renderer::nativeMapCpuServices owns an incarnation token and active-frame guard.
Its pre-load completion opens and closes an empty C3D_FrameBegin(0)/FrameEnd(0)
scope outside active drawing; successful Begin drains Citro3D's actual prior
command queue. C3D_FrameSync is only VBlank pacing and is not the completion
receipt. Shutdown/reinitialization expire copied callbacks before freeing
resources. This is native adaptation of the parent's synchronization boundary,
not execution of the whole original sysWaitDrawSync counter/tick/timeout wrapper.

No native source-map vertex/index/texture/display-list resources are published.
Within that explicit empty GPU-cache domain, range leaves validate owned pool
spans and CPU ordering; vertex invalidation acknowledges an empty native domain.
They never discard dirty ARM cache lines or reinterpret guest addresses as
native pointers. A future GPU/capture owner must replace this admission before
publishing native map resources or acknowledging capture/material children.

## Readiness and Game ownership

Normal startup initializes the CPU process after the existing native UI/animation
startup. `initialized()` does not imply room loading. `loadHarbor()` starts one
actual mapLoad("gor_00"); budget/child holds resume that invocation. G0 remains
source-controlled. At the current boundary the original parent has relocated
D/T, constructed540 objects,98 collision joints and5 lights, loaded the original
C road and read actual shadow projection. It then requests GXBeginDisplayList
at sourcePC8002a360, with a real map-allocated65536-byte temporary. No fixed
capture length, synthetic command stream, object output slot or loaded count is
published. Consumers must not treat these constructed rows as a loaded map.

Game retains the process across room/restore/checkpoint ownership handoff.
Pending map work excludes those handoffs and pauses simulation before animation,
input/event, sequence, audio and camera clocks. The native runtime drains it
outside frames without consuming input edges or accumulating IO catch-up time;
pipe/road/save/reload and exit-save work cannot cross a retained map operation.
Ordinary startup admits Init only; automatic story activation of source Load
must wait for actual capture/material translation. Existing playable room data
is not relabeled as completion of this source owner.

Host validation covers actual cold VM heaps, physical/list replacement, source
publication/clear ordering, prefix budgets, fresh-worker Close retirement,
complete harbor CPU construction, retained capture without prefix replay,
provider loss/recovery and numerical callback invalidation. Native build and
isolated ARM/emulator scope are recorded in [progress](../../PROGRESS.md).

## Scoped acceleration of identity proofs

FieldMapSourceOwner currentness and NativeMapProcess backend currentness use
callback-local raw RAM lookup caching. Each invocation still evaluates its
complete identity graph and reads every SDK header, pointer, list link and
physical backing predicate. No Boolean authorization, payload value or pointer
survives the proof. Pure backend predicates stay on the owner thread with frozen
semantic registries; they cannot mutate mappings, call children or yield.

If an SDK/source operation already holds the raw borrow, these predicates use
that existing lookup cache. A separate evaluated flag distinguishes a refused
nested borrow from an evaluated false predicate: false is returned once without
retry. Live writes to a heap-list word inside an existing borrow must invalidate
and then restore the proof immediately. Foreign physical mappings between calls
remain rejected, including byte-identical replacements. Actual ownership-loss,
allocation, numerical callback and capture holds retain their original semantics.

This accelerates address resolution, not source state or event progression.
Validation and measured host/emulator limits are recorded in progress; no New
2DS XL timing or original-runtime parity follows from a host improvement.


RAM region stores now remain ordered by guest base through registration,
extraction and script import. Lookup selects the preceding base by binary
search, then validates the entire requested range. Owned/external guest ranges
remain disjoint. Live semantic precedence and conservative raw exclusions are
unchanged; cross-region/sparse/unaligned accesses retain byte fallback. Region
ordering is the actual mapping store, with no persistent pointer/value cache.
No registration, extraction, alias admission or original layout is relaxed.
