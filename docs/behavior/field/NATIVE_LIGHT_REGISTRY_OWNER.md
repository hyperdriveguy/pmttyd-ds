# Original light registry and native process owner

This closes the local registry and reached harbor map-light loop. Actual normal
Game/MapEnt dispatch, room retirement, animated lamp matrix producers and GPU
light publication remain open. Creating the original five records in fixtures
is not evidence that the playable harbor now renders those lights.

## Original source boundaries

The read-only US revision0 DOL supplies lightInit at 8001c21c,
lightReInit, lightEntry at 8001bd98 and lightNameToPtr. The reached `_mapLoad`
light loop is 8002951c..8002960c; the complete map loader is outside this change.
Instruction words, hashes and static reference outputs are recorded under
`artifacts/field-light-owner-evidence/`. These are static observations, not
Dolphin or hardware measurements. See [harbor initialization](NATIVE_HARBOR_AREA_INITIALIZATION.md)
and [behavior index](../README.md).

The two descriptors at 8041e650 hold signed counts and guest array pointers.
Only active map group1 at 8041e664 selects the second descriptor. Each initial
bank has32 records of96 bytes. Initialization stores each count before invoking
heap0 allocation and then publishes its returned pointer, including source
null returns. Allocator zero/flush effects belong to that child, not to a
fabricated successful registry operation. Four BSS PAPER/PAPERI/PAPERCRAFT/BooBoo
presets are separate records; their1040 flags do not activate ordinary lookup.
The craft position uses live SDK ZERO and the original scale/multiply sequence.
Reset clears only the captured selected array and wrapped byte count.

Entry preserves the original hard32 duplicate threshold, cumulative formatting
(`x_0000_0001`), fresh count/array reads and source input/store order. The source
full-array path writes one-past; the portable core preserves that operation
rather than inventing a failure return. Original name lookup returns the first
active matching record or guest null. Retained cursors capture only reached
operands, pin installed providers and preserve earlier child effects on waits.

The map loop reloads its table and signed count every iteration. It scales the
original position by the live10 constant, rereads kind pointers after failed
comparisons, defaults unknown kinds to point, reads optional flags only for
magic012d60d8, captures color into its local and calls the real Entry operation.
Entry's returned index does not control the loop. Later waits preserve earlier
records; changing table count can terminate the next reached condition.

## Native ownership and supported domain

`FieldLightRegistryOwner` is stationary and noncopyable. Its two cache-aligned
3072-byte arrays, descriptor bytes, four preset records and private scratch
are external VM RAM, with exactly the same physical bytes exposed to light
queries. No renderer-side record copy exists. A false native cache-flush child
retains the same zeroed allocation for retry. The heap adapter supports the
process's two cold allocations; `initialize` after readiness reports readiness
and does not pretend to execute another original allocation sequence.

Each native invocation supplies its own stationary `FieldLightRequest`. Keep
that token alive across all waits; a different token cannot consume retained
work, even with identical arguments. A future event adapter must own tokens
through the actual event birth/retirement and quarantine pending callbacks.
The VM and borrowed records must outlive their consumers. Owner teardown
conditionally removes only its own backing, preserving a replacement mapping.
Byte-identical replacement RAM cannot impersonate the actual owner.

The typed Entry adapter admits the original stable map-input domain: exact32
capacity, a free slot, attenuation0..3, bounded names fitting the34-byte source
name field and backed position/vector/color outside the light records. It
rejects unsupported full/alias domains before effects. The portable core still
models the wider source behavior separately. Native SDK adaptation covers
finite inputs and retained operation boundaries; full FPSCR/GQR/exception and
nonfinite parity are unproven. It uses no per-frame allocations. Physical
New2DS XL timing/memory and original pixel parity remain unmeasured.

## Original heap allocation admission (2026-11-07)

The owner now accepts an optional `FieldLightHeapServices::allocate` provider.
In that mode `allocationBase` reserves only private scratch; neither bank is
preassigned or mapped during bind. Each reached original allocation calls the
provider with heap0 and3072 bytes. The provider completes original `__memAlloc`,
including its original SDK header/free-list/allocated-list effects and requested
payload clear/cache operations. False retains that call without consuming an
allocation; true returns the exact original guest address, including null.

The owner extracts a nonnull payload from owned VM RAM without changing its
guest address or SDK header, copies its existing bytes into the stationary
aligned record bank, and maps that exact bank back at the returned address.
Native cache flushing of this stable backing precedes pointer publication. A
held flush retains allocation, extraction and mapping independently; it never
repeats the original allocation or clears source mutations made during the
hold. The former fixed-bank services remain available for explicit fixtures.

An optional pure backend `current` predicate checks process/SDK lifetime before
source acknowledgement and at each owner admission, including raw-borrow
identity checks. It must not recurse through this owner. Mapping records retain
address, extent and backing for conditional teardown in either allocation mode.
No callback or consumer may outlive its backend or VM. No SDK free or recovery
allocation is fabricated at teardown.

Original lightInit accepts both null returns and can still finish its preset
initialization. `ready()` therefore reports completed source initialization and
current ownership; it does not prove that both arrays exist. Native selected-bank
operations reject null pointers, and `record(0)` returns no record. An allocation
that returns null just as backend ownership disappears remains the same retained
null call until ownership recovers; its bank index advances only on acknowledgement.

The host regression uses actual `NativeFieldAnimation` cold-process heap0 and
`eventHeapAllocate`, verifies source descriptor pointer order, unchanged SDK
headers and allocation-list membership, distinct header-separated bank addresses,
retained flush mutations, request identity, backend loss/recovery, replacement
mapping teardown and real no-fit returns. This enables the shared map integration;
normal Game light/map ownership and GX capture are still separate pending work.
