# Retained native NPC creation

Original US `npcEntry8004b894` now has a retained constructor boundary in
`resumePackedNpcEntry`. All leaves except `tryPoseEntry` remain synchronous,
fully admitted providers. A pending pose call is no scalar result: it does not
publish handle0 or -2. The actor prefix is the source clear340/flags3/name copy;
P104 remains its actual memset0 until the first pose result arrives. No source
hidden flag, placeholder handle, actor copy or second clear is added.

The cursor retains the source registry, capacity-derived free index, actor,
original name/model pointers and each reached pose call's model/mode. Duplicate
names retain the original independent first-free allocation policy. First pose
mode is sampled after strcpy and stays fixed through its native holds. Only a
completed first result, freshly reread from P104 after its store, can select
exact-2 hoshi fallback. That retry independently samples fresh GP14 and retains
its own arguments. The original model pointer remains the final c_luigi compare
operand even after fallback. Completion observation never repeats construction.

The suffix executes once with original fresh P104 reads for paper/height/radius/
Vivian/light; original root/previous/scale/default stores; fresh GP38/3c capture
and low timestamp store before high; and fresh count from the originally captured
registry. Existing synchronous source tests preserve callback-induced word/owner
changes and source ordering. This is a continuation of the recovered admitted
body, not a new measured timing or general fault/SDK memory domain.

`FieldPosePool::resumeEnter` pins initial resource/model/mode and performs initial
capacity/native producer admission once. Retries call the same actual native
Entry directly. A source model row may already have active flags without an
adopted native resource while file acquisition is pending; repeating ordinary
cacheMetadataReady/capacity admission would deadlock that legitimate continuation.
New Entry waits before actor effects when another Main/selector/presentation
producer owns the animation process. A retained Entry has a separate entryPending signal: its invoking script
resumes it. Mario presentation draining must not consume that signal and skip
simulation. New producers, clock ticks and configuration still wait for Entry;
matching Entry retries can resume it.

`FieldNpcRegistryBinding::resumeEnter` retains this constructor and its pose
children under one shared registry owner. It requires the same facade, GP pointer,
name/model operands and bounded immutable input strings; source selector and
reached timestamp reads remain fresh. Existing `enter` uses an implicit retained
cursor. Multiple facades share a pending-owner barrier: lookup, enumeration,
new registration/entry and reset cannot consume/recycle a partial actor. Bound
Main/whole traversal/tail, direct Draw, clock, actor/wander name resolution and
full setup resumption also defer before effects. An abandoned cursor leaves
its state retained/quarantined by the owner; native cancellation is not invented.
Bindings, VM and actual pose providers must outlive every unfinished invocation.
Owner destruction at process shutdown is not an in-game cancellation contract.

The native pool has a separate raw source Entry path for this constructor.
Original -2 reaches the fallback; ordinary typed callers still receive only
valid handles. `a/hoshi` MODEL and `a/hoshi-` TPL are staged from the existing
unchanged full original bank. Raw hook lifetimes end with NativeFieldAnimation;
typed pool copies do not inherit borrowing providers. Native startup preserves
an explicitly supplied file-yield provider rather than replacing it with its
default staged-ROMFS provider. These providers remain native adaptation, not
GameCube DVD worker or OS timing equivalence.
