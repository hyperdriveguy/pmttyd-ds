# Native item95 registry and original field icon

Finite available-slot mode16 kind95 constructor and ready ordinary camera5
get icon. Source [entry/name/icon contract](../field/ITEM95_ENTRY_NAME_REGISTRY_AND_ICON_DRAW.md)
and [map blend/shadow admission](ITEM95_ICON_MAP_BLEND_AND_SHADOW_ADMISSION.md).
The registry is an ordinary field domain with independent32-slot item and icon
pools; it does not replace key-item pouch capacity121 or alternate-domain storage.

`FieldItemRegistry` preserves first-inactive construction, active duplicate
retention, item name lookup including inactive slots, first-active icon setters,
and name-wide deletion with repeated first-active icon deletion. Names remain
retained in inactive entries; stale names can shadow later duplicates. Get force
writes sequence2/substate0, clears source counters/status10000 and ORs1000;
it neither grants an item nor runs presentation. Subsequent poll mirrors the
source inactive/missing/status2/status10000 completion predicate.

After each item owner callback, `synchronizeIcon` performs the source second
active-bit check before copying item position/scale/alpha. Deleted entries cannot
resubmit their icon in the success call. The batch helper preserves ascending
slot order; original main dispatch must still invoke each item owner separately.
Item mainflag2 and iconflag2 are distinct. Icon100 selects camera5;80 skips the
conditional lighting stage rather than hiding the icon. The mapblend constructor
input retains40 for later material consumption; the current finite draw refuses
that unbound grayscale branch. Deferred metadata2000 is retained but resolution
is pending. Native short-name(max15 bytes) and available-both-pools preflight
are explicit admission policies; full source eviction/overflow and autogenerated
names are unbound, rather than guessed or allowed to overwrite another object.

`item95IconDraw` supplies original40x40/TPL312 geometry at source.6 reduction:
24x24 bottom-anchored quad, white/source alpha, T(position)*Ry(-cameraYaw)*S.
Original descriptor307 remains distinct from TPL312. Alpha255 requests no blend,
GE128 alpha test and depth writes; lower alpha requests sourcealpha blending,
always alpha test and no depth writes. Camera5 viewport depth and reversed native
comparison follow the [existing camera/effect bridge](NATIVE_ITEM_GET_EFFECT6.md).

`Renderer::item95Icon` consumes the existing original icon atlas, with C3D matrix
composition/PICA projection and texture modulation. It accepts only the supplied
matching camera5, restores following UI state and preserves framebuffer alpha.
The lazy32-icon arena is6912bytes, reset once per native frame, with distinct
six-vertex ranges avoiding overwrite of earlier draw submissions. Shared texture
resources are retained by the existing icon consumer; no per-frame texture load
or resampling/tint baking. Explicit retirement and shutdown release only this
arena. Render does not mutate registry position, flags or animation clocks.

Native quest/Get services, original camera4 prepared vectors/queue order,
shadowEntry(camera4,radius10,type2 cylinder), metadata deferred resolution,
map40 material, alternate-domain/full-pool branches, original audio/control and
hardware/GX pixel verification remain pending. Visual harness checks prove this
provider's original bitmap, anchor/occlusion and teardown; they do not grant95,
write5405 or claim an actual playable acquisition sequence.
