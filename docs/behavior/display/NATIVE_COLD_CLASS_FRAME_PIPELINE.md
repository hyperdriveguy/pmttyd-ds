# Native cold class frame pipeline

The class frame pipeline composes the actual queued class callback, retained
DrawMainMenu, observable icon ordering, whole retained circle/bubble children and
finite original-art backend. It owns a stable provider context and pending pass.
Every successful source/SDK prefix executes once. Only whole callback completion
and a complete backend publish an immutable batch; a held later pass retains the
previous completed snapshot. Render admission consumes metadata, never guest
readiness. Pass keys are simulation display identities, not rendered frames.

## Cold stack adaptation

Original DrawMainMenu801160e4 allocates its stack frame0x230 without clearing
position array SP+b4. State0 at80116358..80116380 advances delay/state without
producing transforms. Source80116c40 passes those elements to DrawMainIcon;
80119b2c..80119b48 reads every declared Y before flags80119be0..80119be8.
There is no recovered heap owner for those unwritten stack positions.

The native observable-raster policy supplies no replacement positions. With no
active rows it acknowledges no raster work; with one active row its visible
order is unique. Multiple active rows require real finite, pairwise-distinct Ys
when inactive positions are missing. The original descending all-pairs LT sort
then has a unique visible order; inactive NaNs do not swap. Tied active Ys are
ambiguous: A1/B1/inactive2 reverses A/B whereas inactive0 preserves A/B. They
remain unavailable. All produced positions use the exact original sorter,
including its non-stable ties. Circles require produced positions/matrices/
parameters; lone bubbles need no position that their actual child never reads.
This is native visible-order adaptation, not original stack/FPSCR equivalence.

Source ownership, count, flags and borrowed active operands stay stable through
a pass. Boundary mismatches hold; a mutation inside a provider invalidates that
invocation permanently so it cannot replay acknowledged effects after restore.
Whole source footers remain required, retained children. There are no empty
footer acknowledgements or forced flag1 cancellation/reentry to hide cold entry.

## Actual allocation and font ownership

HarborTutorial now provides a scoped class draw binding over its actual VM and
real cursor lookup. Each successful SDK class allocation gets a fresh native
lifetime token; source release removes it. The binding's current predicate proves
both token and B+1c78, including an SDK address reused by a later source Init.
The predicate holds the native runtime while borrowed memory callbacks exist.
Callers retire display/publication state at UI/battle retirement; the binding
never synthesizes source End or ordinary command/display scheduling.

The frame pipeline requires that current predicate before execution and provider
boundaries. A saved pointer/key alone does not establish current ownership.
Reentrant resume is refused; retirement requested inside a provider is deferred
until its stable context can be destroyed safely. Fresh binding follows explicit
retirement. Actual assets/font/labels must outlive the binding and rendered
snapshots. Only the camera query delegates to the supplied source raster owner;
ordinary raster requests use the actual native backend and loaded original art.

The backend preflights the complete finite FontString run into temporary CPU
geometry/actions. Unsupported later glyphs reject before real RNG or geometry.
Accepted runs synchronously replay each original pair of RNG requests before its
quad. No readiness failure remains after the first effect. This requires
immutable font/label resources and a total synchronous RNG provider that neither
reenters drawing nor mutates resources. It is native atomic SDK admission, not a
replacement original font interpreter or original boot-RNG seeding claim.
