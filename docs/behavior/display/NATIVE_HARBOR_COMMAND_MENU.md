# Native manual Harbor command-menu presentation

This is a presentation policy for the existing manual Harbor tutorial facade.
It makes physical class/weapon/target selection visible on the upper screen,
using the actual copied source rows and original extracted art. It does not
execute or acknowledge DrawMainMenu, DrawWeaponWin, the original target display
callback, CameraMain or a source DisplayQueue. The source-controlled queued
renderer remains separate. A bound source display excludes this manual policy.

The radial selector uses the original circle, speech bubble and class icons.
The native control legend uses the original font with a native one-pixel shadow.
Weapons and targets use the original nine-slice window, pointing hand and font.
Labels remain the actual US message bytes. Only the non-dialogue physical
control legend is adapted. Lower-screen scene/audience rendering is unchanged.
No touch input, generated art, sound, story branch, damage or result is added.
Original asset rights and provenance remain in [ASSETS](../../ASSETS.md).

## Explicit native layout domain

The target is 400 by 240 pixels. The class selector supports up to seven rows,
rotates the actual selection into the focus bubble and keeps disabled icons
in the existing original weighted-gray material. Lists show four rows per page,
with the actual selected source ordinal selecting the page. Geometry is a
provisional native reflow, not measured original screen coordinates or a
recovered source camera. Existing centered half-size native UI transforms are
used once. This is unrelated to the source stack/slot adaptation contracts.

All labels must be nonempty ordinary printable US bytes with real mapped font
glyphs. Unsupported control tokens, absent glyphs/icons and text too long to
remain readable reject the entire plan. They are never stripped, paraphrased or
substituted. Target labels are resolved from the actual source registry unit,
original part lookup rules and part-name message key. Selection reads the actual
manual target candidate byte at B+0x428+0xab7, not a visual actor slot. The Yoshi
special-name path remains unavailable here; the initial Crump path is supported.

## Ownership and completion

A snapshot retains the actual runtime and class allocation lifetime. Legacy
weapon setup has a separate native iteration token minted only in its existing
real initialize callback, before writes. It is not a claimed source allocator
receipt. Targets retain that weapon setup identity even after source W clears.
The actual source menu registration is weakly checked. The facade additionally
uses the existing `NativeFacadeRegistration`, appended last: copy, move,
assignment, replacement or destruction invalidates old native receipts without
changing source runtime sharing or guest state. The snapshot also records the
facade address, actual B/W, menu kind/type, simulation timestamp/turn/phase,
selection and copied rows. Draw and completion recapture and compare the model.
Failed, uninitialized, dialogue-active, phase/attack/damage-active, replaced,
source-display-bound or unavailable models cannot receive a native receipt.

`prepareNativeHarborMenu` runs outside FrameBegin and constructs the entire CPU
plan before exposing it. Actual class-surface and font generations are required.
Drawing preflights every geometry element, resource and both shared vertex-arena
budgets before its first GPU effect. It then checks actual top-target admission
and calls only the existing nonallocating nine-slice and class-batch GPU paths.
Import, allocation, provider calls and resource retirement are forbidden between
that preflight and serialized submission. Missing/partial draws leave submitted
false. Fades do not admit hidden menu readiness.

Only `completeNativeHarborMenu`, called after actual C3D_FrameEnd, may notify the
existing facade's `classMenuPresented` or `weaponMenuPresented`, and only after
full submission and a fresh identical model check. Targets receive no source
queued-callback notification. These two explicit native presentation flags make
the existing physical input owner usable; they do not claim the source animation
or source display parent completed. FrameBegin, imported assets, a prepared CPU
batch and a source callback request alone never notify input readiness.

`retireNativeHarborMenu()` drops only CPU snapshot/geometry references. It makes
no guest writes, End calls or GPU/resource releases. Call outside render after
the application's frame synchronization and before releasing the tutorial's
actual VM/menu resources. Normal complete/rejected frames clear their receipt;
class drawing shutdown also retires it. There are no asynchronous callbacks.

## Validation and limits

Portable tests use the actual accepted original catalogs/font/icon metadata,
with explicitly TEST-only host import identities. They cover every radial
selection, disabled art, multi-page lists, original Crump target label geometry,
missing icons/control tokens, invalid geometry, retired resources, changed
runtime/facade/setup/rows/selection/phase and copy/assignment receipt retirement.
They validate the entire CPU plan rather than acknowledging a successful prefix.
The actual driver confirms dialogue-edge and phase/attack/damage gating; it does
not call readiness notifications or synthesize a physical press.

Focused strict C++17, ASan/UBSan and native ARM syntax checks are recorded with
the package. Existing legacy `harbor_tutorial.cpp` and `render.cpp` warnings are
demoted individually during their integration syntax checks; new translation
units and all other edited translation units pass with warnings as errors.
These focused tests are not a fresh whole-core ABI build or a native gameplay
smoke. The facade gains native identity metadata, so full core/native rebuilds
with matching headers are mandatory. Normal Crump battle/event/action/result
and field-return completion remain owned by their actual gameplay services.
