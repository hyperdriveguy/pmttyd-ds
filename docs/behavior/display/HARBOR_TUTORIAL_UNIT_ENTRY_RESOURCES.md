# Harbor tutorial original UnitEntry resources

The original source bank identity selects CPU MODEL/TPL and descriptor storage;
it is independent of the dedicated native drawing atlas. `HarborTutorialPoseResources`
loads and retains actual original CPU resources for `b_mario`, `c_kanbu`, and
`c_pkr`. It neither allocates source poses nor acknowledges display or GPU work.
The caller must pass the actual source model name to `find`, then use the genuine
process/pool entry provider. The system part's original null bank bypasses lookup.

Original Mario's three parts all enter `b_mario`. They receive distinct live pose
handles from the actual pool; source initial descriptor zero is `M_Z_1`. Initial
shell table strings do not justify inventing a clip or replacing that entry.
The helper reuses existing `trio-attack-goombella` CPU resources for `c_pkr`, whose
first descriptor is `PKR_Z_1`; this adds no helper GPU atlas. Existing model-cache
canonicalization in `NativeFieldAnimation::enterSource` remains authoritative:
an already admitted same-model resource retains its original resource/atlas.

Crump's raw `a/c_kanbu` has 20 original descriptors, beginning with `Z_1`. The
previous dedicated converted bank has only `S_1`, `R_2`, `R_1`, `A_1A`, `A_1B`,
`A_1C`, and `D_1`. The source CPU loader evaluates descriptor zero to admit a
resource, so those seven clips alone cannot admit original UnitEntry. A new
editable Z-only fragment is appended to the **current** dedicated JSON during
normal compilation. Existing edited clips remain first and byte-for-byte
unchanged in the encoded clip payload. Name collisions and mixed pack formats
are errors. No normal build re-extracts or re-bakes checked-in assets.

The one-time empty-destination importer proves that adding original `Z_1` after
these seven poses changes neither their converted data nor the atlas's texture
cell order or pixels. Reference full atlas RGBA SHA-256 is
`f022cacbca2ae54c00a906cd93fd13f41447ff0c22daa1d3838d2f146d04f98e`.
Thus Z_1 uses the same atlas coordinates, including when existing atlas pixels
are edited. Original clipping is static frame zero, with 84 source positions,
126 flattened vertices and 648 node floats. This is source-data evidence, not
an original framebuffer comparison.

`pose-directory` recipes retain original descriptor order/discrete timelines
and copy exact MODEL/TPL source bytes to ignored compiled companions. New tracked
sources are `assets/original/tutorial-unit-entry/crump.model`, `crump.tpl`, and
`crump-z1.json`; individual provenance/license is recorded alongside them.

`077869459c3b3852fdd2f9e531b7894afa1de6c10d6a21f6ab95204edf685ce1`.
The latter exactly matches the already staged `field-native-c_kanbu_ibt` TPL.
Add only the missing `a/c_kanbu` type-5 catalog row before the actual file catalog
is frozen; reuse existing `a/c_kanbu-` type-4 storage. Never mutate or restage an
already-bound catalog to synthesize readiness.

Validation covers actual loader/cache sharing, original initial descriptor
sampling, missing/mismatched backing rejection, five distinct detached CPU pool
allocations and current Crump combat clip sampling, plus exact retained raw
companions and append-only edit preservation. Production source allocator,
heap/alias/animation startup providers, canonical model-cache resource and actual
GPU generation remain the genuine runtime owners. CPU catalog success is not
whole UnitEntry completion, source animation completion, GPU submission, or a
native tutorial playthrough. Unconverted future descriptors remain unavailable;
this package does not claim all original Crump animations are converted.
