# Native process Window startup prefix

This extends the [font startup prefix](NATIVE_UI_STARTUP_FONT_PREFIX.md) in the
same real `NativeFieldAnimation` process. The proposed normal Game entry runs
Font, Window job admission, actual serialized delivery and the original Window
completion before configuring Mario. It does not complete `seq_logoExit` or
activate a battle menu, source camera, inherited GX state or native atlas.

## Source order and ownership

The retained [Window Setup, callback and unpack owners](RETAINED_WINDOW_TEXTURE_SETUP.md)
execute their complete original bodies. Setup `8007fbd8` clears the actual
palette/ready globals `8041ea18/8041ea1c`, then calls `arcOpen` with the original
`font/msgWindow.tpl` string. The finite native archive adapter scans the actual
four 40-byte descriptors at `803ebff0`. Unknown descriptors hold; an active
archive reaches the unsupported original `ARCOpen80078198` and remains held.
Only genuine exhaustion of four inactive descriptors admits the DVD branch.
The archive branch itself never publishes Ready1.

The DVD branch formats the original `%s/f/msgWindow.tpl`, opens a real backed
file entry, obtains its actual length, and allocates/clears the rounded original
palette buffer through the same process heap0 used by Font and Mario. Heap
headers stay in that process. Under a quiescent mapping scope the captured
cleared payload transfers to strong shared backing, preserving known bytes and
unknown alignment tails. A failed mapping rolls back; no allocation is replayed.

`beginWindow` completes only the original asynchronous request admission.
The finite port adapter publishes the exact `DVDReadAsync80144de4/34` entry
fields and flags in source order against the actual entry backing: destination
`+7c`, remaining `+80`, offset `+84`, flag1 set/flag2 cleared at `+90`, callback
`+8c`, and progress0 at `+88`. The job owns the real file handle and immutable
request. It does not emulate the original DVD worker/list subsystem.

`pumpWindow` performs an actual file read after job admission. It validates the
observed bytes against the immutable original file before overwriting the
actual source allocation. Missing delivery admission retains the observed read
without repeating I/O. Equal-byte foreign remaps fail exact backing proof.
Only the actual fresh remaining-count transition to zero clears flag1, sets
flag2 and admits callback `8007fcf0`, with the original entry+40 argument.
Altered nonzero remaining counts remain pending and cannot manufacture a
callback. Completion closes the real handle at the original source Close call.

The callback relocates the actual TPL, allocates the real `count*32` object
array, invokes all 51 original TEX/GX constructors, then executes the original
Ready1 store. Constructor clears, arithmetic, stores and fresh reads use actual
process providers. Missing double subtraction/rounding or SDK dependencies
retain the source continuation. Completed source effects are latched before
later resource-witness capture, preventing source replay on metadata holds.

## Shared resource queries

`windowReady()` describes actual completed source history and live ownership.
`windowObject(index)` additionally checks that indexed SDK object's 32 bytes
against its completed constructor witness and reads its current relocated
palette metadata. The original bank contains formats CMPR14 and I4/0; unsupported
or unknown indexed metadata remains unavailable. Corrupting one object does
not rewrite the original Ready1 or invalidate unrelated indices.

`ownsSourceResource(address,size)` provides first refusal over the actual Font
and Window state/heap footprints and exact imported source spans, including
unknown or retired intersections. `sourceResourceByte/Half/Word` expose only
current, actually known cells in that footprint. They include genuine Ready0
while Setup or delivery is incomplete, and exclude GP, DVD records and unrelated
field VM memory. A partial boundary read holds. Language remains the genuine
shared GP owner and must be bound separately; consumers must not use the broad
diagnostic `word()` method as a mutable-memory fallback.

The process strongly pins shared heap backing; Window mapping/texture owners
retire before process teardown. Consumers pin the same process/UI lifetime.
Actual `windowObject` identity and metadata are required when source LoadTexture
is reached. Neither source Ready1 nor an imported native atlas substitutes for
that proof, camera publication, native texture generation or GX history.

## Focused validation and limits

Strict host tests execute actual original Font→Window Setup→real file read→all
51 TEX/GX constructors→Mario Entries/tick, each admission hold without replay,
missing arithmetic, active/unknown archive frontiers, altered remaining count,
entry/backing replacement, two-VM known/unknown heap aliases, indexed metadata
mutation, Ready0 resource reads, language persistence and retirement. Owned
replacement code receives ASan/UBSan; the accepted root archive is not
instrumented. Strict ARM syntax covers owner, memory, tests and exact Game/main
postimages. Python tests pin original bytes/BSS/catalog and preserve edited
outputs. Existing source verifiers pin complete Setup/callback/Unpack/TEX/GX.

This finite startup port supplies actual file delivery, heap transfer and
serialized callback ownership, not disc hardware emulation. Active archives,
other DVD jobs, later LogoExit children, normal battle scheduling/GPU admission
and full original startup remain explicit external owners. Nintendo and
Intelligent Systems retain original rights. No license or redistribution right
is granted by extraction; ISO, raw files and compiled packs remain ignored.
