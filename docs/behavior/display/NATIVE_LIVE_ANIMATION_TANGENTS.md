# Live source animation tangent storage

AnimationTangentMemory attaches the already-generated178 binary32 words at
803d9580 to BattlePosePool's retained AnimationTangentTable. VM loads/stores and
both native cubic kernels consume the SAME big-endian bytes. No independent
float cache, regenerated table or copied static asset replaces this owner.
The original [producer](ANIMATION_POOL_AND_TANGENT_INITIALIZATION.md) and
[cubic consumer](ANIMATION_OUTPUT_INTERPOLATION.md) remain the source authority.

## Binding and lifetime

Bind requires the actual source-array guard in the SAME VM, matching source work and no
competing tangent owner. It reads the complete existing table. An already
retained CPU table must match every byte; otherwise attachment holds without
changing either view. Owned source RAM is extracted, then registered as an
external view of the retained table. Registration failure restores extracted
RAM and does not publish a provider. A readable external table is insufficient
for extraction; it is never silently replaced.

AnimationStartupProcess attaches this table only after the complete cold parent
and source work/cache alias admission. Failure retries attachment without
replaying source heap allocations, tan calls or file references. ready() requires
both owners current. Tangent aliases retire before array aliases and VM storage.
Detach copies CURRENT bytes back to VM RAM and preserves the CPU table. Neither
view rewinds to cold values. Reattachment requires equal retained/current bytes.
The owner borrows VM storage; callers keep it alive and may not independently
replace/unregister its mappings. Native use is serialized, without source
concurrent-writer/interrupt semantics or arbitrary mapping mutation claims.

Pool copies deep-copy table bytes and clear alias ownership, like other retained
native pool state. Detached CPU copies therefore preserve their own current
values while the original VM continues changing its table. No shared mutable
static table leaks between these native copies.

## Consumer and availability rules

actorNodeDelta/evaluateSelected and sampleActorAnimationCache accept an explicit
live table. Source-backed pose entry/adoption and BattlePosePool evaluation pass
that table. Each admitted cubic entry decodes current incoming/outgoing binary32
values from its BE words. VM word/byte edits immediately affect later CPU cubic
samples; changing and restoring a table entry changes and restores the actual
Goombella node output without cache drift.

A source-attached typed pool refuses entry/evaluation if its tangent owner is
missing or detached. It must not fall back to the legacy table or sample stale
retained bytes while separate VM RAM changes. This is a native ownership
admission before effects, not a new guard in the original Main body. Detached
legacy animation packs retain their existing explicit native-libm table path;
detached copies of a source-backed pool instead use their retained table.
Existing source-fixture owners now bind the actual table generated by their
complete initializer, with their heap/file fixtures still declared separately.

Outgoing signed angle outside(-89,89) still skips cubic. Incoming angles outside
-89..88 remain unsupported by native pack admission/cache sampling; there is no
clamp, fabricated adjacent table data or claim to the original broader domain.
Native tan/FMA/rounding adapters remain unchanged. Live ownership does not prove
Gekko libm, FPSCR, denormal, paired-single or physical performance parity.

## Output migration still required

Source P48/4c and50/54 are distinct cumulative/output vector buffers; P60/64
count scalar floats from MODEL140. Visibility58/5c shares MODEL13c bytes.
Texture68/6c shares24*MODEL12c bytes with selector, padding and five floats.
Source texture replay changes byte0 and float4/8; other fields must survive.
These real BE scratch buffers remain authoritative. Native std::vector<float>
outputs cannot alias them directly on little-endian ARM. W.e8 redirects only
position/normal outputs to W.f8/fc; node/visibility/texture buffers stay perpose.

The next integration must migrate sampler, traversal, texture, fan and flush
consumers together, using actual captured source pointers and decoded read-only
shape snapshots at the appropriate points. Writing detached CPU vectors back
over source allocations would introduce conflicting authorities. This change
closes live tangent ownership only. Ordinary Game activation, full output/ring/
facing/link/release/GC/clock and complete prologue remain unfinished. Read-only
layout/source review: artifacts/animation-output-evidence/.
