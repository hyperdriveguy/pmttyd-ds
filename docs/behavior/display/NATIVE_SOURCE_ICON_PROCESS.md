# Native original icon process contribution

`NativeSourceIconProcess` binds one actual cold `NativeFieldAnimation` VM and its
actual GP registration. It runs the complete retained
[IconInit/callback bodies](RETAINED_SOURCE_ICON_SETUP.md) with the
[real raw assets/shared memory](NATIVE_SOURCE_ICON_MEMORY.md). This is a bounded
native startup contribution. It does not acknowledge whole LogoExit, DVDMgrMain,
GXInit, source rendering, a queued callback, or normal battle activation.

Admission checks actual process readiness, no pending Entry/Release or populated
pose slots, and the same selected GP registration through held startup. The
source32-byte Icon globals must be genuinely unmapped at cold admission; no
producer is adopted from matching bytes. A weak native registry permits this
contribution only once per actual process owner, including after retirement.
It pins no otherwise dead process and rejects address reuse with a different
process owner. Replacing the GP registration cannot authorize a second IconInit
in the same surviving process. This metadata is not an original ready flag.

The source heap provider calls actual `eventHeapAllocate(0,size)` in that VM,
retains one allocation per reached source callsite through transfer waits, and
moves only the actual payload RAM into stable shared backing. Source allocator
headers remain in the VM. Original memset calls execute actual `eventFillMemory`
over already admitted actual heap bytes; no rendering/GPU acknowledgment is
required for these CPU effects.

Two finite native152-byte DVD records receive actual raw filename, logical
length, flags/mode and source-installed userdata. Their address policy uses a
checked native range60040000+i*152 only after actual `unmappedRange` admission;
these are not claimed original SDK allocations. Open uses real `rb` files;
missing native files return actual open0. Async admission captures exactly the
source handle/destination/rounded length/offset/callback and owns coherent entry
fields. This does not emulate the whole source DVD manager/threads.

`begin()` completes only source Init/job admission. `pump()` separately performs
one actual file read, validates every byte against the original preflight, and
for BIN appends the real18-byte physical-disc suffix from the private pack.
Transfer/delivery/callback policies may hold without repeating any allocation,
read or successful callback. Actual delivery updates the original worker's fresh
remaining/progress/destination fields and flags. The actual callback receives
entry+40; source callback secondArgument+2c therefore reads the genuine userdata
at entry+6c. TPL runs whole palette Unpack before Close/ready1. Both final flags
come only from the original final source stores. No native import sets them.

The exact formatter journal extends the existing retained finite native formatter
with the two original Icon plain%s callsites. It checks actual source format
bytes, actual source DVD-root VM bytes, private destination identity/capacity128,
and retains partial admission. It is not general printf/SP emulation.

Optional reads give unknown/stale owned memory first refusal. Raw constants are
exact original address views; actual VM supplies root/GP/SDK data outside them.
The owner uses a weak-State/strong-process proof holder, so surviving memory
services retain a real VM without a State cycle or dangling userdata. Retire
unmaps while VM is pinned; it runs no invented guest End/free and rejects later
admission. Caller must retain the actual owner and serialize providers/mappings.

The actual-VM test uses the terminal boot35 core/archive and all matching frozen
headers/RomFS, overlaid only with these new headers and the exact formatter
postimage. It proves4 real heap allocations/transfers,2 workbank clears,2 actual
jobs/reads/deliveries/callbacks/closes, both ready0 before delivery and1 afterward,
all8192 original BIN bytes and613 relocated image descriptors across actual VM
aliases. Every transfer/delivery/callback holds twice; reentry, GP registration
replacement, repeated begin/pump, explicit retirement and facade lifetime cases
are tested. Native SDK objects, sourceIconGX packets and resident GPU imports
remain separate next owners; source-ready alone cannot acknowledge those leaves.
