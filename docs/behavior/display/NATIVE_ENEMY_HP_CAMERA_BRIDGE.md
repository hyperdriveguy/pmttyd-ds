# Actual queued HP camera bridge

`BattleEnemyHpCameraBridge` admits only actual camera8 dispatch of original
BattleDrawEnemyHP8011fde0. It uses the shared camera ownership engine behind
`BattleClassCameraBridge`; the class public entry still admits only8012210c.
Private friend-only binding selects one of those two fixed original callbacks.
No source record, callback identity or guest field is rewritten to enter either
adapter. Actual original camera Main/Draw and queue invocation remain required.

## Shared actual producer and lifetime rules

Bind the same real shared CameraManager bank with an actual allocation generation,
actual actor memory services, an explicitly selected native address reservation
and its unmapped proof, and the required successful-Main epoch predicate.
The predicate must verify the exact current allocation and actual successful
Main producer pass, retain actual owners, and be pure/non-reentrant. The shared
engine still requires actual completed Main, active Draw stage8/current camera8,
actual invoking dispatch and matching queue.current callback/userdata.

Camera4 and8 must have actual published finite matrices. Their copied view,
projection and yaw bits are checked against the shared bank at every provider
boundary through a held call. No boot-projection-only admission, fixture lens,
identity camera8, sourceunit*100 conversion, clamping or fallback view is supplied.
The existing native SDK/finite arithmetic adapters are reused, without claiming
original FPSCR, GQR, paired-single or GPU pixel equivalence.

Each actual DisplayQueue.reinitialize count reset also increments native
resetEpoch metadata. It starts1; reaching unsigned64 maximum transitions to
poisoned0 and remains0 forever. The engine and HP source frame capture a nonzero
reset epoch and compare it through holds. Reset followed by identical record
repopulation cannot reuse the borrowed invocation. This native lease check does
not alter original queue count/current/dispatch behavior: the underlying
DisplayQueue dispatcher still resumes an already captured invoking callback
when source count becomes0. No guest write or guessed original condition is added.

Keep actual camera state and the borrowed Main/Draw/queue owners immutable
through synchronous source reads and callbacks. Finish only after whole source
HP callback completion and all required source child work, immediately before
returning success to the actual dispatcher. A new pass requires a strictly
increasing actual producer key. Retire is metadata-only; retire dependent source
cursors before releasing/rebinding the camera context.

## Typed copied-position ABI

The original HP parent already owns a copied XYZ local with its original unit
offsets applied. `project(borrowedXYZ)` uses a native typed overload of
`packedBattleScreenPoint`, without allocating a synthetic guest stack address.
That overload captures actual camera4 before copying the borrowed XYZ. It shares
the exact same post-camera implementation as the existing guest-address entry:
SDK view at camera+11c, SDK project at camera+15c, then fresh source304/240/0
constant reads in their original order. Output stays unavailable until both SDK
providers complete. The old guest API retains its original camera→three guest
position reads→SDK→constants ordering.

The shared engine applies its finite-domain/output and epoch checks around this
same helper. `word` exposes actual source-style camera yaw/view/projection words
through the caller's native view tokens. `camera(8)` and current-camera lookup
return the actual admitted camera8 token; `matrix` delegates existing real SDK
adapters. The full owned range is reserved even while unavailable. Never fall
through to unrelated guest data inside it; no zero-value missing-word sentinel
is installed. Total memory readers require prior immutable epoch admission.

## Publication boundary and validation

Camera epoch availability gates held source entry/resume only. It must not be
combined into the longer actual-allocation predicate used for completed source
batch publication: copied geometry needs no camera after finish or normal queue
reset. Actual allocation and GPU residency/generation proofs remain necessary
for publication/draw. HP packets already include model/view transforms, so a
presentation owner must use the real projection-only native raster view, not
the last number icon's model/view transform.

Focused tests run actual CameraManager Main/Draw and actual queued HP dispatch,
reject the class callback and unpublished boot views, verify actual source-unit
projection and word views, typed copy-after-camera and constant order, unchanged
output on missing providers, changed allocation/pass/matrix/range admission,
HP and class reset/repopulate rejection, and original count0 dispatcher behavior.
Existing guest ScreenPoint and class-camera regression tests remain unchanged
and pass. These tests do not activate normal tutorial scheduling or prove native
GPU/hardware output. Product source Main/sequence, actual memory/resource owners,
ordered publication and final GPU draw remain required.
