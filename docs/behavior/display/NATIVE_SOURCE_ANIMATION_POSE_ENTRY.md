# Original pose Entry on the native cold owner

enterAnimationPose implements the complete US animPoseEntry8004176c/4ec body,
including its original model/texture scans, reference increments, filename
requests, failure paths, timestamps, buffer child and final defaults/sort owners.
The source contract is [pool provisioning](BATTLE_POSE_POOL_PROVISIONING_AND_TYPED_NATIVE_ADMISSION.md).
The production bridge is AnimationStartupProcess::enter; it runs this body over
its real cold SDK arena, shared file manager and aliased256-pose registry.

## Retained original body

Each of306 original body instructions has an explicit continuation. This is a
fixed translated function, not an interpreter accepting executable images. The
cursor captures register values, condition and CTR only as needed to preserve
read/store/child order across unavailable primitive services. Successful parent reads/stores never replay. Child providers retain their own
prefixes, references and formatting while held. A different name/mode cannot
replace a held request. Complete result-2 is distinct from unavailable.

Pose/free-slot scans capture one W/count and reread the array base each row.
Active model/texture scans capture the signed limit but reload W/base each row.
An active model compares loaded MODEL+4, through its actual FileEntry+a0 holder.
A texture compares its actual FileEntry+20 filename. The selected row survives
strcmp/fileFree holds. References use wrapping words, not saturating counters.
Source exhaustion reaches its original null memory access; the adapter does not
invent a graceful source-1 result or reset a live pool.

Model null handle or null payload decrements its model reference and returns-2;
the payload-null branch first performs actual fileFree. The stale model file
word survives. A null TEXTURE handle has no equivalent rollback: Entry proceeds
to pose timestamp and AllocBuffer. Native metadata adoption then requires a real
texture identity. No source repair or substituted success is supplied.

Source stack+8 filename has retained semantic string backing. Child requests
mark stack arguments instead of constructing a fake guest stack address.
Source sprintf uses %s/%s-, original prefix a, loaded MODEL+44. fileAllocf uses
%s/%s and the original name address; formatting completes before retained
_fileAlloc/Yield. Native wrappers admit only these formats, serialized supported
filenames and stable real backing. Generic varargs/thread scheduling stays open.

The timestamp reads hardware bus clock800000f8, then GP, then GP40/44 for mode0
or GP38/3c otherwise. The exact mulhwu/shift divisor feeds signed64 __div2i.
LOW is stored before HIGH. The bridge reuses the explicit native signed divide
adapter; absent/zero divisor remains unavailable. Callers must publish their
actual native clock/bus owner; test162MHz is an explicit fixture policy, not
an ISO-initialized word or measured hardware clock trace.

Actual animPose_AllocBuffer receives the captured pose POINTER and runs the
existing retained scratch/recovery machine with real loaded MODEL counts.
Only after it completes are material/color/rate/identity defaults published.
Native PSMTXIdentity admits constant zero/one on stable pose RAM, retaining the
source paired-store order as word pairs; SDK mutable constant domains remain
separate. Sort compares the original name against four original strings, and
stores actual live Vivian-tail pointers or default80415dc4, not detached values.
Unmentioned stale pose fields survive. There is no whole-pose memset.

## Resource adoption without source-state replay

After full Entry completion, the bridge validates actual loaded MODEL names,
counts/flags, texture filename, positive model/texture refs and matching converted
resource identity. It prepares real descriptor0 CPU shape/cache workspace, then
attaches sidecar resources and native generation. Adoption never calls typed
enter/restart and never rewrites the authoritative BE pose/model/texture rows,
clock, references, source file handles or scratch pointers. A held adoption does
not replay the completed source parent. CPU workspace is still separate from
source scratch vectors; their authoritative output integration is required before
ordinary Game activation. [Tangent consumers](NATIVE_LIVE_ANIMATION_TANGENTS.md)
now share the actual initialized source table.
