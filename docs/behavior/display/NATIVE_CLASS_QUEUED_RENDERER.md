# Native original class callback and ordered submission

The native Renderer now prepares a concrete binding for the actual Trio class
UI allocation and dispatches original callback `8012210c`, camera8. It reuses
`BattleClassNativeFrame`, the complete existing DrawMainMenu/controller/raster
pipeline, original US labels and the genuine common-bank file owner. It does
not register a substitute callback, create an audience population, force a
readiness byte or activate the original whole battle Main.

Preparation occurs outside FrameBegin. The actual surface/icon generation,
footer generation, Renderer font/icon imports, copied original font metadata,
real VM/UI allocation and original label/RNG resource owner remain current.
Renderer shutdown retires the frame binding before freeing its texture owners.
Copied icon frames use a retained simulation tick, including across child waits.
Actual original RomFS catalogs and textures must remain unchanged while this
binding is active; this is the native process resource policy, not an invented
original allocation-generation field. No source string is rewritten.

Concrete numeric services use the [actual camera bridge](NATIVE_CLASS_NUMERIC_PROVIDERS.md).
Footer services bind original party/pinch/button controllers, the actual VM
change-position query, original GetItemOn and complete TexturePlane2 through
its real palette/descriptor/GX/FIFO owner. Four private query outputs are native
locals; the original cache XYZ reads still occur even though the footer only
consumes the index. Query cache stores, W+120 spin mutations and retained sound
boundaries remain source ordered. There is no fabricated private guest stack.
An actual sound owner remains required for the audience/party sound arm; recording
a sound request never acknowledges it. Public footer reentry is rejected.

The frame owns a copy of its backend. Narrow footer append/raster APIs route
only the currently executing original footer children to that exact copy.
They reject calls outside the live callback, during retirement or after camera/
allocation loss. Geometry is retained in original request order; no separate
later footer overlay substitutes for it.

The first source-queue visit can prepare geometry before the independent native
world adapter. Its actual GPU submission holds until that world and the original
HP layer have drawn. Renderer resumes the SAME callback and camera pass afterward;
it does not restart a source invocation or advance source UI timing twice.
Only successful actual `drawClassMenu` submission permits camera.finish and queue
advancement. Failed GPU admission retains source completion, immutable geometry,
callback identity and camera ownership. A successful submission is never replayed
after a later guard failure. Allocation loss poisons the frame until explicit
retirement. The arena resets only after FrameBegin synchronization and is not
reset between these two queue visits.

If a source callback is suspended and its UI/texture allocation becomes stale,
preparation cannot silently replace its context and replay the prefix. The
binding remains unavailable until actual VM retirement/cancellation. Callback
contexts stay pinned until the in-flight invocation returns, including recursive
metadata retirement. No native destructor performs original UI End/free work.

This binding is reachable when the actual source queue emits the class callback.
The current ordinary battle still uses legacy active sequencing; original entry/
whole-Main scheduling, weapon table/target/payment/sound/effect owners and complete
selected-tap lower-scene publication remain unfinished. Existing class sorting
admits only observable active operands; unknown source private coordinates are
never filled with guessed values. See [frame scope](../battle/NATIVE_CLASS_MENU_FRAME.md).

Host checks exercise retained source-to-submit waits, copied footer ordering,
service replacement, reentry, poisoned allocations and no replay. Separate native
visual evidence at `artifacts/radial-menu-native-probe/manifest.json` renders the
original Jump/Hammer menu and physical navigation with an explicit test camera/
scheduler. Its legacy Harbor sound fixture records requests without playback;
its inactive-slot policy is explicit. That probe proves neither this ordinary
production entry path nor original executed-PPC/stack/framebuffer equivalence,
full audio ownership, hardware performance or a completed tutorial/battle.
