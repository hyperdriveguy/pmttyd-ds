# Harbor queued original menu Renderer consumer

This increment selects actual Harbor bindings from
[HarborSourceMenuFactory](HARBOR_ACTUAL_SOURCE_MENU_BINDINGS.md) in the existing
native Class/Weapon Renderer contexts. It reuses their retained native Frames,
original circle/bubble and submenu surfaces, actual font/window providers,
ordered packets, immutable GPU leases and whole-batch preflight. The binding
record types retain their existing names; no Trio VM, battle state or synthetic
menu rows are created.

## Source and native ownership

Trio selection stays on its existing active path. Harbor selection requires a
real running Harbor scene and an actual factory; the factory additionally
requires actual B, W token, common file ownership and the genuine source camera
receipt. The source allocation generation remains independent of the Display
producer generation. The consumer never stores W+14, calls a native presented
helper, selects a command, samples Pad or advances simulation/action timing.

A Renderer context pins the selected factory identity. While a source draw is
held under that same factory, loss of a GPU/resource proof cannot discard and
rebuild its source prefix. Real source/runtime retirement may release it.
`resumeHarborCommandDisplay` accepts only original class8012210c or
weapon80121ce8. The factory checks the actual invoking queue record and passes
its real retained Main/Draw/queue to the existing Frame. Unknown callbacks,
including original Target80120a44, remain unavailable.

The public callback entry rejects calls outside a native FrameBegin..FrameEnd
interval. The Harbor class submission and weapon ordered tryDraw also check
that native interval before GPU effects. A previous render's submitReady flag
cannot authorize a tick-side GPU call after FrameEnd. This is native submission
availability; it is not source UI readiness or a camera receipt.

The real Window surface is admitted outside FrameBegin, after genuine
NativeUiStartup windowReady, before a new ordered weapon binding captures its
resource. No texture import occurs in a source callback or while replacing an
incomplete source cursor. Original sourceReady0 behavior in the linked Window
owner remains independent of atlas availability; no source readiness is copied
from this native import.

## Outer cadence

The original source DispMain child completes its actual registrations and seals
the actual [Display pass](HARBOR_SOURCE_DISPLAY_PASS.md). This consumer never
begins, registers, seals or activates one. It calls `Factory.resumeDisplay` at
Renderer's existing visits before the world layer and, when an actual menu
submission waits, again after the world layer with native submission enabled.
The runtime is pinned for that entire resume.

Source Main registration completion and whole CameraDraw completion are distinct.
The root scheduler must block its **next** CPU/input admission until
`DisplayPass.complete(capturedPass)` succeeds. Retain all actual queue entries,
Main/Draw cursors, camera bank, source children and provider owners across GPU
waits. Do not advance simulation ticks/action-command time because another native
render attempt occurs. Repeated completed display resumes have no source effects.

The root must bind `DisplayBinding.callback` to this actual callback dispatcher
and supply genuine CameraMain/CameraDraw/DisplayGX services. Those services must
reject GPU effects outside the active native frame and restore their own retained
native state when needed after an independent world pass. A missing provider
holds; this increment does not acknowledge camera/GX requests with booleans or
supply a field-view/battle-camera substitution.

## Validation and remaining frontiers

Private verification compiles the actual journaled Class/Weapon/native dispatch
translation units plus factory with strict ARM flags, and the journaled main
Renderer with only existing baseline warning exemptions. Actual VM/common TPL/
US-message Factory tests additionally exercise the outer resume with no implied
registration/seal, a real invoking queue record and rejection of recursive parent
resume. Host and owned-module ASan/UBSan pass. This is not native GPU execution,
a full fresh Game ABI link or normal Crump menu activation; root owns those gates.

The exact 25-anchor consumer journal is over immutable11047 plus frozen Factory5.
A live-anchor audit found every anchor unique despite concurrent field/Crump atlas
lease edits; replay the narrow replacements, never copy the complete old
render.cpp over those edits. This package changes no assets or licensing.

Concrete pending providers remain: the real field initializer's camera receipt,
actual battle camera Main/GX adapters and complete source draw registrations,
source Icon8 native binding for reached class/subIcon/cursor icon children, and
original Target draw. Existing source font, cost and Window owners stay genuine;
any reached unavailable leaf retains its original hold. Physical directional,
A/B/X paths stay in original source command Input. No touch command hitboxes or
lower-screen panel are introduced; the audience scene continuation is unchanged.
