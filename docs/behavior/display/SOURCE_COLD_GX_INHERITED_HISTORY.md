# Source cold GX contribution and inherited state

The native cold UI process may execute the supported contribution from original
US `__GXInitGX802b2a24/938`: the actual private fog-color capture defined by
`lwz r3,r2+1fa8` at `802b2a44`, the loop initializer at `802b3078`, and the
complete operations from `802b3088` through `802b3220`. This is **84 native
semantic setter effects**, from 24 static call sites with two sixteen-iteration
loops. It does not acknowledge or prove that the original SDK parent, GXInit,
DEMOInit, Logo, or omitted setup work executed or completed.

The actual call chain in the read-only original DOL is DEMOInit8002ed08 at
8002eee0 to GXInit802b2424, then GXInit at802b2a08 to __GXInitGX. The verifier
pins all three complete source bodies and child-call censuses, the supported
412-byte range, and immutable initialized data804293e0..f7. No original binary,
raw asset, guest stack address, or synthetic source register is installed.

The verifier pins the original scalar definitions in initialized data. Native
code ports only ordinary numeric operands: packed color0 and binary32 float
literals0,1,.1. There is no extracted byte-blob/code array or embedded asset.
The native private fog-color capture has the actual constant0 value; later fog
arguments preserve source bits `{0,1,.1,1}`. Source type0 disables fog. No native
constructor supplies mutable BSS or unknown source bytes. These numeric source
operands do not require a fabricated VM mapping or repeated source reads during
packet replay.

The contribution performs every source operation in its supported range:

- Sixteen iterations of KColorSel6, KAlphaSel0, and raster/texture swap0.
- Four actual swap tables, including identity table0 `{0,1,2,3}`.
- Sixteen direct TEV stages, NumIndStages0, and four coordinate scales0/0.
- Fog0, disabled fog-range adjustment, source blend tuple0/4/5/0.
- Color/alpha writes1, ZMode1/3/1, ZCompLoc1, dither1, disabled destination
  alpha0, pixel format0/depth format0, and field mask1/1.

Earlier cold Cull2 at802b2d98 is deliberately **unknown** in this bounded owner.
The real [class primitive](ORIGINAL_CLASS_SURFACE_PACKETS.md) issues Cull0 itself.
The cold contribution does not invent any earlier cull, channel, descriptors,
material, matrix, texture, or source color/alpha-comparison state.

`SourceGxInheritedState` binds a strong independent actual process owner, a pure
long current predicate and a separate real cold-admission predicate. Binding is
one-shot. Cold initialization runs only before any previously recorded setter,
once per owner, with the actual cold admission accepted. Repeated completion
queries do not replay it. Missing cold admission holds without effects. The
84 operations are fixed, validated, nonallocating logical native effects; no
external child or RNG can partially suspend them. They establish the relevant
source state used by finite native packet rasterization, without pretending to
write the original SDK GXData cache or hardware FIFO.

Subsequent `apply` calls must represent **actual reached source setters**.
Typed calls carry original function identity, optional callsite provenance,
argument count, raw integer fields, and exact fog float bits. Recognized
nonordinary values update the history and prevent future compatible capture;
malformed or unsupported calls fail atomically. Callsite numbers alone are not
admission evidence. Native C3D setup/imports cannot manufacture source history.
The real caller must route every source write to a tracked field, including
ColorUpdate/AlphaUpdate from real DisplayQueue dispatch. At camera8 both are1;
camera4's actual alpha0 must be recorded, too. Local InitSub Cull0 and actual
font/icon/window setter effects feed the same process owner where applicable.

Any opaque/unowned source work that might change tracked state calls
`invalidate` before future capture. This drops known fields without replaying
the cold contribution or invalidating already copied packets. An unsupported
setter must not be silently acknowledged or leave stale known history. A native
world draw alone is not evidence of the original world material routines.

`capture(stages)` admits 1..16 source TEV stages. It requires fog disabled,
color/alpha writes1, identity swap table0 and selected stage swaps0/direct,
NumIndStages0, disabled fog-range adjustment/destination-alpha, original
RGB8/depth format0, dither1 and field masks1/1. Dither has no color reduction in
this admitted RGB8 domain. The selected packet's own linked leaf retains actual
TEV inputs/material, channel/texture/matrix/geometry, cull/blend/depth and GPU
resource proof separately; this snapshot is not their substitute.

Each immutable snapshot copies all known source evidence and pins a separate
long process proof. Legitimate later circle/bubble/font changes do **not**
invalidate prior loaded packets. Camera.finish does not retire the process.
Actual process retirement/current loss permanently invalidates the snapshot;
address reuse or a new history owner cannot revive it. Source-time currentness
and long packet currentness remain separate. All public service boundaries
reject self-reentry, and a current callback retiring the owner cannot admit an
effect or packet. Destruction explicitly retires outstanding snapshots.

The unapplied NativeUiStartup journal binds an independent holder of the actual
NativeFieldAnimation process and its actual GP registration token. It runs this
bounded cold contribution before the existing source US GP/Mario contribution
and whole FontManager. Strong proof does not retain the startup State or create
a Context/history ownership cycle. Explicit startup retirement/destruction
retires the history before its proof userdata can disappear. No font/window
readiness flag is written by this contribution.

Focused host and sanitizer tests cover cold admission, all sixteen stage
records and exact operands, ordinary/nonordinary mutations, write-mask camera
transitions, snapshot survival through later setters, unknown history,

Strict ARM syntax and static original-source pins are separate validation.
Full native setup scheduling, callback routing and actual queued menu GPU

does not establish normal battle/tutorial entry, whole Weapon rendering,
