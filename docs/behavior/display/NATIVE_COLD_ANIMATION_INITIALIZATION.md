# Retained cold animation initialization

`initializeAnimation` implements complete animInit80042854/274 over retained
word/store/call services, an atomic double-word memory read and typed double
`tan` service. Original source publications and dependencies are recovered in
[pool initialization](ANIMATION_POOL_AND_TANGENT_INITIALIZATION.md). Private
fresh listings, source bytes and static implementation review are under
artifacts/animation-cold-start-evidence/. No original execution is claimed.

This is a cold parent, not a live-pool attach/reset API. Original marioStInit
calls it before npcInit and subsequent field pose creation. Normal native Game
already creates three Mario poses; invoking cold init afterward would replace
live pools and discard ownership. The normal bootstrap therefore remains held
until genuine shared W/SDK heap/file and typed output bindings exist. A completed
fixture parent does not acknowledge that production startup boundary.

Each initial count publication reloads current W80415dc0. Counts64/64/256/1024
and cursor0 drive ordered heap0 allocations for16-byte model,12-byte texture,
170-byte pose and12-byte auxiliary records. Sizes read current counts and wrap32.
Allocation return stores through a fresh W; We8=0 is interleaved before auxiliary
allocation. Explicit scalar stores preserve untouched W fields, including f8/fc.
No blanket W clear, local null rejection, old-pool cleanup or implicit retry is
introduced. Heap provider owns original zero/flush effects and actual allocation.

After explicit104/10c zeros, retain the literal scratch null branch and request
heap0/180000 only if current104 is null. Capture fresh W, load factor8041fbb4,
read that W104, load bias802c1070 as ONE retained64-bit memory value, then publish
that W108. Factor/bias are captured once. For indices0..177, source integer-bias
conversion subtracts in double then rounds binary32; multiplication by captured
factor rounds binary32. Pass its widened value to tan802724e8, retain the double
return, round binary32 and store803d9580+4*i. A pending table store never repeats
the completed tan call. No finite guard, static imported tangent asset, exact-pi
replacement or reordered sample generation is introduced.

File requests preserve type0/literal-format identities802c11d8(a/vivian.bin)
and802c11e8(a/ag2tg.bin), with no extra format operands. Nonnull Vivian handle:
read H+a0 holder, capture destination WORD80415db4, read captured holder's payload,
then memcpy_as4(destination,payload,c00). Reload holder/payload before copying
payload+c00 to80415da0 for16 bytes; then fileFree the captured handle. Null skips
copies/free. Archive setter0 precedes ag2tg request, whose returned handle,
including0, publishes to freshly loaded W100. Real file-manager reference,
collection/relocation/archive lifetime stays with the provider; C++ destruction
or a direct file read is not a substitute for that source graph.

Original initialized Vivian destination is WORD80415db4=80305900;
80415da0 begins0000000000000002ffffffffffffffff. Original pointer cells and
constant bytes are not permission to reset live history. Tests explicitly own
those source-address views. Source ag2tg41984 bytes and Vivian3088 bytes are
exported unchanged with pinned SHA/offset provenance by
`tools/animation_startup_assets.py`; no texture or geometry conversion occurs.

`nativeAnimationTangent` adapts double tan through native libm. Ordinary legacy
cubic consumers share one generated178-float table in animation_tangent.hpp,
using the same binary32 degree factor and widened-angle native libm contract.
This removes duplicated table generation; that table does not yet alias a live
source VM tangent owner. SDK/Gekko numeric equality and live initialization
cadence remain unproven. Legacy field presentation remains active while original
bootstrap ownership is completed.
