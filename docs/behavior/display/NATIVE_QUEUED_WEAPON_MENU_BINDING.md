This increment connects the actual queued callback `80121ce8` to the existing
whole retained WeaponFrame/Disp/DrawWeaponWin source graph and ordered native
publication. It does not register that callback or activate original battle Main.
The new renderer route is an exact unapplied integration journal until its owner
applies and validates the complete graph. Physical input remains owned by the
original command/menu controllers; there are no command touch rectangles.

The binding requires the real Trio VM, current original `B+1c78` UI allocation
and its actual allocation token, successful CameraMain pass, invoking original

One explicitly supplied private 32-byte output address has initially unknown
bytes. It is admitted only outside the real source camera reservation and all

It is a native private-output policy, never a claim about a guest SP address or

## Retained public-owner lifetime correction

A retained source-memory/frame bundle must not dereference its former public
`TrioAttack` or `Game`. Weapon factories now bind a weak per-facade registration
whose lifetime belongs exclusively to that actual public selector. The token
stores a weak runtime identity and a weak source-memory cache. Retaining the VM,
files or an immutable packet cannot keep the registration alive. All four weapon
current predicates reject expired/mismatched registration before guest/provider
reads; actual allocation, bank and camera/pass checks remain independent.

Copy construction shares original runtime storage while obtaining an independent
lazy registration/cache. Same-runtime assignment preserves the destination's
registration. Reset/cross-runtime assignment and destruction expire its token;
move expires the moved-from token and keeps the destination token only when its
runtime identity is unchanged. No token claims a new original guest generation
or completed source call. Actual UI End still retires the allocation; the live
source-only memory adapter may remain valid for the still-owned original VM.
The legacy class factory remains separately documented as a borrowed-facade API.

The registerable lifetime regression includes the exact production Trio TU only
in its test target, with a narrow friend to enter genuine retained UI Init/End.
No product test method, synthetic allocation token or camera pass is supplied.
Heap-facade destruction, retained bundles, copies, self-copy/self-move, same/cross
runtime assignments, moves and real allocation End are checked under ASan/UBSan.
Focused linking executes no Game object compiled with the older public layout;
the integrating owner must rebuild the complete Game/Renderer/native ABI graph.
