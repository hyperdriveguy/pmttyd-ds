# Native Harbor Star Point presentation

This native presentation policy consumes the retained original Star Point constructor/Main owner. It renders existing original icon 404 during the manual Crump tutorial; it does not allocate a guest EffectEntry, acknowledge original queued Disp, award EXP, or complete original End.

## Original evidence and art

Original Disp `8020ae8c/e4` builds root translation, camera-4 negative-yaw rotation and particle translation, then calls iconDispGx `8001a6e0` with flags 0 and icon 404 for each nonzero particle alpha. Alpha is a visibility test, not a color multiplier. Existing whole SourceIconGX applies world scale .6 and bottom anchoring: the original 40-pixel icon becomes source x [-12,12], y [0,24]. The native scene scales source positions by .01. The current tutorial presentation camera has yaw zero; this is an explicit native camera policy, not an original camera-4 callback receipt.

The existing message-icon catalog supplies loop 1, four 40x40 frames, delay 6, original descriptor 6050 and TPL descriptors 418..421. No new image is imported. Editable pixels remain `assets/original/ui-message-icons/atlas.png`; normal compilation overlays these pixels. Nintendo and other original rights remain retained; this feature grants no additional license. The 512x1024 shared atlas already occupies 2 MiB; this consumer allocates no duplicate texture.

Original Entry/Main/Disp evidence is retained in `artifacts/crump-star-effect/{entry,main,disp}.dis`. Numeric data and source simulation belong to the separate original Star Point package, loaded from `romfs:/harbor-star-point/memory.pmevt`, with no numeric defaults. Ordinary icon color is read from actual source DATA at 8041f864 before admission; the supported native material requires its alpha to be 255.

## Admission and lifetime

Preparation runs outside FrameBegin and pins actual tutorial runtime identity, imported texture object, pixel allocation, metadata, program and a private resource epoch. Before constructor RNG, the native owner reserves exactly six vertices per requested particle in the first free instance slot. Held constructors retain request and source callback identities, successful source prefixes and the same arena. There are four independent slots, each bounded by the original-source consumer policy of 100 particles. Allocation failure does not retire another active effect.

Runtime advances source Main using simulation visits. Raster replay never advances Main, samples RNG or writes rewards. The upper view builds and preflights the entire geometry before copying buffers; the lower continuation reuses those buffers at the same simulation tick with its own clip proof. Finite binary32 clip products and sums are checked; finite offscreen, singular and transparent cases are not culled by invented policy. Nonzero alpha preserves the source color unchanged.

Retirement invalidates the resource epoch before callbacks can use Renderer, then synchronizes C3D before freeing each arena. Runtime references are weak; late callbacks reject after retirement. Ordinary scene retirement and renderer startup-resource teardown must apply the supplied exact journals. There is no normal activation claim without those hooks and the separate source/event owner.

## Validation and limits

Focused strict host tests use the actual compiled message-icon catalog. They cover frame selection, dimensions/UV rejection, .6 bottom anchoring, nonzero/negative alpha visibility, hidden unknown coordinates, geometry bounds, overflow rejection and finite singular/offscreen matrices. Geometry plus the real catalog loader pass ASan/UBSan with leak scanning disabled. Both new display translation units pass strict ARM syntax against a consistent private copy of the accepted Victory headers and the peer's declared Star Point facade API.

No native Star Point screenshot, original framebuffer comparison, full native build or fatal-round source/event completion is claimed by these focused checks. The parent must run combined make test/make all and the actual fatal-round smoke after integrating the peer source package and normal numeric product recipe.
