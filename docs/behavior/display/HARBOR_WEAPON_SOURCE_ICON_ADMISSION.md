# Harbor queued weapon source icon admission

This increment connects the existing [whole source Icon owner](WEAPON_SOURCE_ICON_PACKETS.md)
to the real retained weapon callback `80121ce8`. It also applies to a Trio
weapon callback through the existing source-selection path. It does not start
a source battle, complete a target menu, or publish source readiness.

## Reached source children

The existing color Matrix entry `8001a4bc`, plain Matrix entry `8001a6e0` and
Position parent `8001a93c` remain the complete retained CPU source bodies.
Class MainIcon, SubIcon and WeaponCursor delegate to that same genuine child.
The actual `NativeSourceIconProcess` supplies the relocated original palette,
BIN, TPL and bytes. TEX and GX Init/LOD construct a real 32-byte private SDK
object before the loaded snapshot is copied. Private address `60018020` is a
native reservation, separate from common-bank TEX at `60018000`; every real
VM, startup, icon resource and all thirteen virtual camera ranges have first
refusal. No image index is used as an object address.

Actual camera 8 supplies matrix, projection, viewport, scissor and depth for
the executing queued pass. Native residency is queried without importing from
a source callback. A missing resident original image holds its reached Load,
marks the actual pending pin, and is imported only by the existing pre-frame
preparation route. The pin is registered before the first Load, including the
already-resident path. Retirement retires its admission; no GPU-prefix replay
or source-ready store is introduced.

## Per-pass inherited-state evidence

Every reached actual source Load still captures fresh inherited GX evidence.
`SourceGxInheritedState::ownsSnapshot` checks the actual private lifetime
identity and currentness. Byte-identical evidence from a different history
owner is rejected. Ordinary and grayscale source profiles remain separate;
a grayscale program's own swaps do not require inherited ordinary state at
every later setter.

`BattleWeaponIconEvidence` reserves one pass's evidence storage before that
pass's first icon Load. Only complete byte-identical records with the same
stage count and actual GX owner are deduplicated. Successful retain does not
allocate, evict a previous witness, invoke source work or acknowledge a child.
The native capacity is the existing mixed packet budget, 4096, plus one
pending source Load. This is a native admission policy, not a measured game
limit. Whole source children retain their captured snapshot across a held Load;
retries do not create additional evidence. The source owner's generic vector
capture is not claimed allocation-free.

The mutable callback context owns the current pass helper. The ordered batch
stores a typed strong reference to that exact helper on its first successful
icon append. The prepared raster plan owns that batch. Advancing to the next
completed pass discards only the context/publication reference to the previous
helper. An externally retained older batch or plan keeps its immutable
witnesses alive. No cross-pass evidence vector is stored in `RootProof`.

The root proof pins the real public-runtime registration, allocation, common
bank, shared source process, source Icon process and actual GX history
identity. Its runtime/allocation guards run before Icon-process VM reads.
The pass helper pins this independent proof; the proof never pins the helper,
child, publication or context. Later legitimate source GX writes and temporary
SDK-object reuse do not invalidate copied evidence. Actual process, history,
Icon resource or UI-allocation retirement rejects it.

## Ordered and native admission

The optional trailing ordered-binding evidence callback is absent only for
batches with no icon packets. Icon append requires an actual current nonempty
pass helper. Once a pass accepts an icon it rejects replacement by a different
helper, including same-address aliases with a different control block. Font
reservation, mixed source order, whole source completion, seal identity and
nonfailing GPU commit semantics remain in the existing ordered owner.

Ordered seal/submit and native raster whole-batch preflight validate the
retained helper before GPU mutation. A bare icon packet plus residency cannot
certify source lifetime. The no-icon path remains independent of icon startup.
The helper is an ownership receipt for the actual Icon child; it cannot make
arbitrary caller-created packet geometry source-derived.

## Validation and remaining boundaries

Focused host and sanitizer tests use the actual original Icon startup/raw
resources and TEX/GX bodies with explicit test camera/residency. They retain
ordinary and grayscale source profiles, exercise waits, and preserve original
successful child behavior. Separate ordered tests run 256 changing-history
passes, retain pass 1 while newer passes complete, prove intermediate helper
expiration, and reject missing/replaced/retired helpers. Cross-owner identical
bytes, resource retirement and recursive calls are tested. ARM syntax checks
cover the actual private runtime and all changed ordered/raster implementations.
These are not native GPU or normal tutorial activation claims.

The actual field camera producer receipt, source Main/Draw scheduling, native
font/window resources and independently current Icon process remain required.
Unknown world/map/light Icon branches hold. Target display `80120a44` is still
a distinct unbound source callback. Physical Circle Pad/D-pad/A/B/X remain
original source input; this increment adds no touch command hitboxes.
