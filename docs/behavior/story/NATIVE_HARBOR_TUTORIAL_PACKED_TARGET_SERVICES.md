This is an incremental combat owner, not a complete playable tutorial or source
runtime comparison. See [init/phase](NATIVE_HARBOR_TUTORIAL_INIT_AND_PHASE.md),
[source target interfaces](../battle/BATTLE_TARGET_EVENT_INTERFACES.md),
[packed candidate protocol](../battle/BATTLE_ENEMY_CANDIDATE_SAMPLING.md),
and [conclusion barriers](../battle/NATIVE_CONCLUSION_AND_EVENT_BARRIERS.md).

`HarborTutorialPacked` provisions one packed battle registry inside the existing
HarborTutorial EventNativeRuntime. There is no second event interpreter. Native
addresses are provider policy: Battle84000000, three0x1000 unit slots84100000,
three0x1000 part banks84200000. Live shared pointer8041eb90 points to that owner.
Actor IDs remain Crump0, Mario1 and neutral NPC Goombella2. Registry insertion
precedes each actor's source init event. This remains a scoped entry adapter;
complete BtlUnit_Entry resource/status/pouch/teardown services are not claimed.

Source kind pointers, raw kind IDs, membership, move-phase, HP/FP, unit
attributes, parts definitions/linked lists, defense tables, pose tables, part
attributes/counters and original position/hit/sampling offsets are retained.
Mario's actual entryunit_mario80416a50→kind80372afc provides all three parts;
no generic one-part surrogate is used. Native part storage preserves definition
IDs. Unit body scale1 and fresh side-facing bytes are explicit ordinary-entry
adapters. Fresh group configuration2/1/0 and side-direction1/−1 are the same
bounded prologue adapter as the existing native battle services, pending full
source setup/RNG/pouch/flag ownership.

The existing public three-actor projection remains stable for Game/Renderer.
Source semantic leaf updates publish at USER_FUNC boundaries; recovered native
services read/write the same packed owner and immediately refresh that projection.
Position/work/HP queries observe preceding source writes in the same VM pass.
Message talk/stay and original M_N_2 pose-time/animation acknowledgement remain
owned by the existing presentation projection. Rendering frames do not advance
phase clocks.

Recovered native Get/SetUnitWork, HP/maxHP, GetPos/GetHomePos/GetHitPos and
Start/StopWait now bind directly to this memory. Wait registration/deletion uses
original tracked290 IDs and source owners. Init IDs record at288; source phase
creation uses priority10/flags20 and records29c without cancelling an old handle.

The external dispatch bridge still requires completed intro and no active phase/
attack root; this is not a complete source turn/action controller.

Original GetEnemyBelong8010eed4 maps signed0→1,1→0,other→same. SamplingEnemy
8010b664 resolves actor/side/weapon in source order, reads actual weapon64/68,
signed-narrows the negated group-direction bias (and its optional second reversal),

Numeric helpers use existing native binary32/stdmath adapters. Target choice
uses an explicit fresh seed0 BattleRandom provider, pending source seed and

flag2's actual field producer remains unbound. The current semantic init's1000
fixture selects the normal enemy branch. This does not prove initial source
first-strike configuration or a global tutorial command restriction.

homing8012be38 after real side/sampling/choice services. That request remains
