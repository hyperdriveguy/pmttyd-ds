# Native Harbor encounter field context

`NativeHarborEncounterField` gives one fresh `HarborEncounter` VM actual NPC,
setup and field-battle owners. This is a bounded native constructor policy; it
does not prove original FieldArea initialization, battle Main, or a playthrough.
The existing legacy `begin` remains unchanged. The unapplied fresh
`beginNativeField` integration is separate and must not be enabled until its
reached external children have real providers. No late admission is supplied.

## Ownership and admission

The context is uniquely owned after its Runtime's actual VM member, and is
therefore destroyed before that VM. Its immutable config pins the actual native
animation process and source snapshots, shared service userdata lifetime, actual
host facade proof, and original Encounter birth pointer/proof. The current
callback receives the actual VM and facade. A mismatched caller facade is
rejected before the callback, including a copied Encounter while the original
remains alive. VM/facade/host proofs are checked before borrowed VM/Game access.
The actual Game callback must additionally require its current host slot,
`&game.harborEncounter == facade`, `facade->nativeFieldVmIs(vm)`, and actual
Harbor room/admission. A visual actor slot is not that admission.

Construction is single-threaded and quiescent. A failed prepare may have already
performed genuine source/native allocation writes; it is not a transactional
rollback. Its VM must be torn down or separately recovered, not blindly retried.
The optional borrowed registry binding must belong to this VM and survive the
context. The shared owner must alias this VM and the animation pose pool.

`advance` services genuine file/retained child work and admits a VM manager
visit. Constructor readiness means both actual Entry `90505208` and placement
`905052f0` roots retired with opcode 2. Cancellation is not readiness. Actual
regular events for the original two sailors have real VM IDs and original setup
metadata. The beforebattle root `90506314`, priority 10, is created only after
both roots finish; its original LW0 fresh/resume branch is retained.

## Start, wait and unowned callbacks

The existing [native field sequence](../field/NATIVE_HARBOR_FIELD_SEQUENCE.md)
owns actual Start/Wait/GetRegularId. Only a completed real Start SeqSet produces
a sealed native battle ticket. Entry requires the actual battle birth identity;
return requires its actual completed retained teardown receipt. Public numeric
results or manually constructed receipts do not certify completion. Source Wait
still owns its original post/control/BGM children.

Unowned original callbacks use the explicit optional config `call`. A missing or
empty result holds; it is not success. The external provider must retain each
actual entry/call's own partial work, preserve original source semantics and
handle genuine retirement before releasing retained work. Context identity and
current checks surround the callback, and recursive calls are rejected. No
legacy environment `80151e0c`, reaction `8006c3c4`, or SFX `801521dc` no-op
acknowledgments are reused. No scene-to-registry writes, fake IDs, menu readiness,
field result, or story advancement are synthesized.

The private fresh-facade test deliberately leaves unowned callbacks unavailable,
so the real beforebattle root stops at its first reached provider. Constructor
and TEST setup-RNG fixtures do not stand in for those source callbacks. The
production Game hookup, actual native movement/control/camera/message/reaction/
audio providers and later original afterbattle tail are separate integration
work. Preserve the working legacy dialogue until that path is actually admitted.
