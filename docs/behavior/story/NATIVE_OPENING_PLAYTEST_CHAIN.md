# Native opening playtest chain

Normal boot owns the original37-message demonstration, then title, four native
file slots and the original new-file opening. A/START can request the title;
a natural unskipped demonstration waits at its final source button guard.
Selecting an empty slot starts the11 original opening message payloads, with
source speakers and house/letter/map/voyage/prologue/wake/arrival order. The
voyage retains its explicit input gate. Completing arrival saves source story3
at the harbor and admits the field owner. Existing native slots can resume
field progress; old-save compatibility is not a prerequisite for this goal.

Story3 plays the original Goombella/Crump encounter messages016..021. Story4
owns the original132-command before-battle event and its source position poll,
messages022..024, parallel charges, HP minimum and setup2 battle-start request.
The field event retains that blocking call while the tutorial owns presentation.
Source tutorial init/phase executes t1_000, actual actor poses and clip-end waits
on the original selected stage/music. No ordinary development battle replaces
this source encounter. Battle results remain pending until a real battle owner
publishes them; result0 is not victory, story5 is not synthesized and saving
remains blocked during this unfinished battle.

The current source attack adapter owns packed units/parts, work/HP/hooks, actual
enemy target selection, Crump approach/jump and precheck services. Original
fresh pouch and Mario init/wait hooks are bound; defense reads explicit physical
PAD samples. Shared counter/hit-event services retain original cancellation and
priority rules. Full damage/reaction, legitimate first-turn/command/attack
ownership, turn progression, death/end/reward/field return are ongoing work. Original cutscene cover geometry, outer projection, tree
motion, fade/light/environment and some effects/sound requests also remain open.
This chain is an early native slice, not full-game or original-image equivalence.

The physical PAD producer continues during frontend ownership. Restoring a new
field Game retains its history, so held A from final dialogue does not create a
second jump edge. Fresh simulation/menu ownership remains separate from that
global input history. Native clip-end callbacks use simulation elapsed time and
original clip spans, never rendering frame counts. Isolated emulator scripts
use generated project fixtures/profiles only.
