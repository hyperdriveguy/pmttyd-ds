# Native original harbor before-battle event

The native `HarborEncounter` executes the original132-command
`gundan1000tai_beforebattle` at gor REL0x2639c, SHA256
`4cc7e8fba986105d05f73b8c21bea7c79e4b69e1fae556f88f4920f77fd97bef`.
`tools/harbor_event_assets.py` reads the US ISO read-only, preserves command
words/control flow and relocates source ADDR32 pointers into authored native
section bases. Original module0 callback addresses remain identities; unknown
or unbound blocking services cannot advance the event. The existing event
interpreter owns waits, integer comparisons, local copies and independent
inline constructors. No narrative text or flattened replacement script is used.

After source021/story4, the event's fresh LW0=0 entry polls integer-decoded
position Z<=-100 AND X>=-25. Source Q1024 float storage and truncation toward
zero remain in the VM: X=-25.5 admits and Z=-99.5 does not. The LW0=1 resume
branch restores Mario(-220,15,90), actors55/105/135/160, original rotations and
flags, before polling. Source control/key ownership is retained; native key
input is blocked after admission. The source clamped reposition, Goombella
movement and camera requests precede022/023/024 with original speaker keys.
Source subordinate charges remain independent inlines while Crump's owner
move blocks. Pouch HP is read from native progress and the source conditional
sets5 when admitted; this is not an authored heal trigger.

The source request binds Crump to numeric battle setup2, then calls the original
battle-start service. Native execution currently retains that command as a
**pending service**; it does not start the ordinary development battle harness,
fabricate a battle result, write story5 or dispatch the postbattle scene. Full
original tutorial battle services remain the next required integration. See
[configuration](HARBOR_TUTORIAL_CONFIGURATION.md) and
[original scene bindings](STORY_HARBOR_OPENING_BINDINGS.md).

Native render/message consumers share the actual source actor positions and
print-entry anchors. Mario's original M_I_N/M_N_H effect-bank clips and ordinary
M_S_1/M_W_1/jump clips use original a_mario textures; no pose aliases or redraws
are fabricated. Camera requests use the existing source interpolation adapter.
NPC movement uses the existing native linear speed bridge; original driver
stepping/easing/collision, automatic poses and display yaw remain unbound.
Environment/effect/SFX calls retain raw requests and remain pending presentation
backends. Crowd setup belongs to the preceding scene/init and is still unbound.
The VM does not claim a complete original scheduler, field main-loop or hardware
trace. Active-event saves remain suppressed until event persistence exists.

The stationary near-equal-height normal-Mario jump uses the scoped source
kernel documented in [field jump](../field/FIELD_SCRIPTED_STATIONARY_JUMP.md).
Nonstationary, roll or unsupported parameter domains stop at their native
service boundary. The landing support remains a native geometry adapter.

Verification must include original-data VM playback, fresh3→4 integration,
resume/poll boundaries, source source HP/charge/jump requests, and an isolated
native checkpoint capture. A pending battle-service notice is a development
notice and must not be presented as original story dialogue or full opening
completion.
